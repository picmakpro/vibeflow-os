    Phase 35 ne concerne QUE ce dépôt, D-10). Contrat de l'interface :

    - `--refresh` : effectue la sonde réseau si le gate d'âge l'autorise, met à jour le cache, ne
      produit rien sur stdout. C'est le mode appelé en arrière-plan.
    - `--print` : n'appelle JAMAIS le réseau ; lit le cache et écrit UNE ligne sur stdout si et
      seulement si une version strictement supérieure au seuil est publiée. Silence total sinon.
    - `--hook` : le mode démarrage de session — équivaut à `--print` puis relance `--refresh` en
      arrière-plan (détaché, entrée fermée, sorties redirigées), et sort 0 quoi qu'il arrive.
    - `--status` : diagnostic humain, écrit le contenu du cache (version installée, dernière
      version vue, horodatage du dernier appel) sur stdout, sort 0.
    - `--if-older-than <N>d` : surcharge du gate d'âge, défaut 1 jour (le « cache quotidien » de D-10).
    - `--help` : l'aide dérivée de l'en-tête, comme les autres scripts du dossier.

    Mécanique, chaque brique reprise du patron cité en lecture préalable :
    - **Seuil** : la Phase 35 se déclenche sur une version STRICTEMENT supérieure à `1.10.0`. Poser
      ce seuil en constante nommée en tête de script, surchargeable par variable d'environnement
      pour les tests, et le documenter comme le contrat de WKTR-01.
    - **Sonde** : `npm view @opengsd/gsd-core version` — la version `latest` du registre. Ne jamais
      demander un dist-tag de préversion. Gardée par `command -v npm` : npm absent ⇒ même
      traitement que réseau KO.
    - **Comparaison** : la fonction `newer()` de `check-plugin-update.sh`, reprise telle quelle
      (`sort -V`), jamais un test de chaînes.
    - **Cache** : un fichier JSON sous le répertoire de cache utilisateur déjà employé par
      `check-plugin-update.sh`, avec un nom distinct pour ne pas entrer en collision avec le cache
      du plugin. Champs : version seuil, dernière version vue, indicateur de dépassement du seuil,
      horodatage du dernier appel réussi. Écriture atomique tmp+mv, verrou `mkdir` avec péremption.
    - **Gate d'âge** : avant tout appel réseau, comparer l'horodatage du dernier appel réussi au
      gate (défaut 1 jour) ; trop récent ⇒ sortie 0 immédiate, silencieuse, sans réseau.
    - **Réseau KO** : si la sonde ne rend pas de version, NE PAS réécrire le cache — l'état
      précédent est conservé et la sortie reste 0 et muette. C'est la garantie que la sonde ne
      transforme jamais une panne réseau en signal (ni en effacement de signal).
    - **Discipline des flux** : tout diagnostic va sur stderr ; stdout ne porte QUE la ligne de
      signal en `--print`/`--hook` et le diagnostic de `--status`. Le silence signifie stdout
      strictement vide (un démarrage de session sain n'injecte rien).
    - **Codes de sortie** : 0 dans tous les cas nominaux et dégradés (advisory, ADR-031) ; 64 pour
      un argument inconnu ou une valeur de gate manquante. Aucun autre code.

    Ne pas modifier `check-plugin-update.sh` ni `update-banner.sh` : ce sont des scripts de module
    `conductor` (polarité gouvernance), la veille gsd-core est un outil du dépôt.
