1. **`claude plugin list --json` existe et rend exactement ce qu'il faut.** Sortie = tableau plat
   d'objets `{"id": "<nom>@<marketplace>", "version", "scope", "enabled": true|false,
   "installPath", ...}`. C'est une source **structuree** de la presence ET de l'activation : elle
   rend inutile le parse de la sortie decoree (glyphes) que le cadrage envisageait, et inutile la
   jointure `installed_plugins.json` x `settings.json`. **Cette decouverte remplace la piste
   « parser la sortie decoree » comme source primaire** — la sortie decoree devient un repli.
2. **`installed_plugins.json` reste inutilisable pour cette tache** : il ne porte AUCUN champ
   `enabled`. C'est precisement la raison du trou. Ne pas s'en servir comme source d'activation.
3. **`claude plugin enable <plugin> -s|--scope <user|project|local>` existe** — le remede
   non-interactif d'un etat `disabled` est un `enable`, pas un `install`. Verifie via
   `claude plugin enable --help`.
4. **Le cas de doublon est reel et mesure sur cette machine** :
   `frontend-design@claude-code-plugins` -> `enabled: false` (scope project) ET
   `frontend-design@claude-plugins-official` -> `enabled: true` (scope user). Des `id` strictement
   identiques apparaissent aussi plusieurs fois avec des `scope`/`version` differents
   (`superpowers@claude-plugins-official` x 3). La regle « au moins une entree du meme nom active »
   est donc obligatoire, pas defensive.
5. **`VF_SCOPE` est deja exporte par l'engine** (`vibeflow-update.sh:78`) : le hook post-install
   n'a rien a passer, le script en herite.
6. **`copy_module_scripts()` pose `<module>/scripts/*.sh` a plat** dans `$TARGET_ROOT/scripts/`
   avec `chmod +x` (`vibeflow-update.sh:342-344`) : le script sera disponible cote lab en
   `.claude/scripts/ensure-design-deps.sh`.
7. **Ne PAS creer de nouveau fichier `tests/test-*.sh`** : `check-version-sync.sh:126` compte les
   suites par `find "$ROOT/plugin" "$ROOT/scripts" -path '*/tests/test-*.sh'` et compare aux
   « N suites » des 2 README racine (52 affiche, 52 reel). Un nouveau fichier ferait rougir le gate
   et forcerait un edit des README racine, hors perimetre. Les cas vont dans la suite existante
   `test-design-orchestrator.sh` — c'est deja la forme du modele (`ensure-deps.sh` est teste par
   T2..T2n **dans** `test-dev-orchestrator.sh`, pas par une suite dediee).
8. **Precedent JSON en script de module** : `check-plugin-update.sh:41-58` lit du JSON via
   `python3` avec le garde de stub Microsoft Store (ADR-054, detection par CHEMIN
   `''|*WindowsApps*`, repli `python`), pas via `jq`. C'est la forme a repliquer.
