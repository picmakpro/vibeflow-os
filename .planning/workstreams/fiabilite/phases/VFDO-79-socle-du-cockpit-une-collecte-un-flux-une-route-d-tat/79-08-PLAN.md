Une ligne `user` ou `assistant` sans horodatage lisible rend la voie inconnue (R10) ; une ligne sans `type`, ou d'un autre type, est ignorée (le `type` est le sélecteur, pas un champ requis).
R3. Jetons : à chaque ligne `assistant` portant un `message.id`, `plierMessage` applique : même identifiant que `dernierMsgId` = la dernière ligne remplace l'usage du message (l'ancien usage est retiré des sommes, le nouveau ajouté) ; autre identifiant = le message précédent est clos (son contexte entre dans `maxClos`), le nouveau compte. `entree`, `sortie`, `cacheLu`, `cacheCree` somment les usages finals des messages ; `contexteDernier` = `contexteDe` du message courant ; `contexteMax` = max(`maxClos`, `contexteDernier`). `compteurs.reponsesApi` compte les ouvertures de message. `modeles` : au plus 4 modèles distincts dans l'ordre d'apparition, motif simple (lettres, chiffres, `.`, `_`, `-`, `:`, `/`, 64 caractères au plus), le reste est ignoré.
R4. Appels : un bloc `tool_use` (`id`, `name`) augmente `compteurs.appels`, entre dans `curseur.ouverts` sous son identifiant avec `v` (verbe de la table fermée par `etiquette`), `t` (instant) et `c` (classe : `humain` pour `AskUserQuestion`, `agents` pour `Agent`, `Task`, `SendMessage` via `ATTEND_UN_ENFANT`, `autre`). Le nom de l'outil n'est jamais gardé. `Agent` et `Task` ajoutent `[id, t]` à `curseur.lancements` (256 au plus, les plus récents) et un événement `dispatch` sur la voie du lanceur ; `AskUserQuestion` augmente `compteurs.questions` ; `SubagentHandback` pose un événement `rapport` sur la voie qui rend. Un bloc `tool_result` (`tool_use_id`, `is_error`) retire l'appel ; `is_error` vrai augmente `compteurs.erreurs` et pose un événement `erreur`. `ouverts` : 64 au plus, les plus récents. `compteurs.refus` : ligne `user` dont `permissionDecision.decision` vaut `reject`.
R5. Humain : ligne `user` dont `origin.kind` vaut `human` : événement `humain`. Champ facultatif : absent, jamais une erreur.
R6. Système : sous-type `compact_boundary` : `compteurs.compactions`, événement `compaction` à l'instant de la ligne ; sous-type `turn_duration` : `compteurs.tours`, `etat.finDeTour` vrai, `etat.agentsFond` = `pendingBackgroundAgentCount` entier positif ou 0.
R7. Segments : entre deux lignes datées consécutives (avant, courante), instants croissants, l'écart prend le genre fixé par l'état après la ligne avant, dans cet ordre : appel de classe `humain` ouvert : `attend-humain` ; appel de classe `agents` ouvert, ou `etat.finDeTour` avec `etat.agentsFond` supérieur à 0 : `attend-agents` ; tout autre appel ouvert : `travail` ; écart d'au plus 180 s : `travail` ; `etat.finDeTour` : `repos` ; sinon `silence`. Après la ligne courante : ligne `assistant` : `finDeTour` = (`message.stop_reason` vaut `end_turn`), `agentsFond` = 0 ; ligne `user` : `finDeTour` faux, `agentsFond` = 0. Un instant qui ne croît pas ne crée aucun segment et ne fait jamais reculer `fin`. Les segments de même genre contigus fusionnent ; 500 au plus (les plus récents gardés, `tronque` vrai) ; les durées (`travailS`, `attenteHumainS`, `attenteAgentsS`, `reposS`, `silenceS`) sont les sommes en millisecondes de `curseur.etat.msParGenre`, arrondies à la seconde à chaque écriture de la voie, jamais recalculées des segments gardés. 500 événements au plus.
