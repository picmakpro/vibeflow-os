## Risques / points d'attention

- **Le tag est la règle non négociable du repo.** Une release sans tag est précisément ce qui a fait diverger
  `main` en juillet 2026 (v2.10.0 → v2.16.0 publiées sans tag). Ne pas clore la phase avant le `✓`.
- **Ne pas taguer avant le merge.** Le tag doit pointer le commit de release **sur `main`**.
- **Cinq fichiers de version à bumper, pas trois** : les deux README comptent (badges inclus), c'est explicite
  dans le `CLAUDE.md`.
- **La version citée dans ADR-055** (plan 14-05, ligne « Contexte : release v2.29.0 — planning-core v2.4.0 »)
  doit correspondre. Si le numéro change, revenir corriger l'ADR.
- **Numérotation** : capacité rescopée → **minor** des deux côtés. Pas un patch (le comportement du verbe
  change), pas un major (aucune API cassée pour les labs non-dev).
