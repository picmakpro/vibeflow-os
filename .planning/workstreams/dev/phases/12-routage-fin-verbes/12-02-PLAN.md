# Plan 12-02 — Les 17 verbes neufs de `dev-orchestrator`

## But

Livrer le niveau 1 du routage pour les intentions aujourd'hui sans porte d'entrée : 17 verbes qui
délèguent chacun à une cible GSD existante. Rend vrai le critère de succès 2 du ROADMAP pour la
partie `dev-orchestrator`.

## Exigences couvertes

VERB-02 (17/18 — `vf-ingest` en Phase 13, cf. D-02), VERB-03 (application du gabarit).

## Tâches

Un `SKILL.md` par verbe, sur le gabarit `12-DESCRIPTION-TEMPLATE.md` appliqué **mot pour mot**, et
sur le patron de corps de `skills/vf-map/SKILL.md` (délégation + reframe + enchaînement typique) :

| Verbe | Cible(s) GSD | Démarcation obligatoire |
|---|---|---|
| `vf-secure` | `gsd-secure-phase` | ✘ revue de code générale → `/vf-review` |
| `vf-testgen` | `gsd-add-tests` | ✘ recette / valider que ça marche → `/vf-test` |
| `vf-gaps` | `gsd-audit-uat`, `gsd-audit-fix`, `gsd-validate-phase` | ✘ revue d'un diff → `/vf-review` · **✘ conformité du lab / agents → `/vf-audit`** |
| `vf-forensics` | `gsd-forensics` | ✘ bug applicatif en cours → `/vf-debug` |
| `vf-inbox` | `gsd-inbox` | ✘ ouvrir une PR → `/vf-ship` |
| `vf-milestone` | `gsd-new-milestone`, `gsd-complete-milestone`, `gsd-milestone-summary`, `gsd-audit-milestone` | ✘ éditer une étape → `/vf-phase` |
| `vf-phase` | `gsd-phase` | ✘ planifier le contenu d'une étape → `/vf-plan` |
| `vf-undo` | `gsd-undo` | ✘ reprendre le fil → `/vf-resume` |
| `vf-backlog` | `gsd-review-backlog`, `gsd-capture` | ✘ explorer une idée floue → `/vf-explore` |
| `vf-cleanup` | `gsd-cleanup` | ✘ clore un jalon → `/vf-milestone` |
| `vf-resume` | `gsd-resume-work` | ✘ où on en est → `/vf-progress` |
| `vf-pause` | `gsd-pause-work` | ✘ livrer → `/vf-ship` |
| `vf-docs` | `gsd-docs-update` | ✘ comprendre le code → `/vf-map` |
| `vf-learn` | `gsd-extract-learnings`, `gsd-graphify` | ✘ cartographier le code → `/vf-map` |
| `vf-explore` | `gsd-explore` | ✘ concevoir une solution (idée déjà formulée) → `/vf-brainstorm` · ✘ code jetable → `/vf-spike` · ✘ figer le QUOI → `/vf-spec` |
| `vf-spike` | `gsd-spike` | ✘ idéation → `/vf-explore` · ✘ implémenter pour de vrai → `/vf-execute` |
| `vf-spec` | `gsd-spec-phase` | ✘ le COMMENT → `/vf-plan` · ✘ idéation → `/vf-explore` |

Règles de rédaction communes (rappel du gabarit) :

1. Description = formulations réellement tapées en FR, pas d'étiquettes abstraites.
2. Contre-exemples `✘ pas pour <geste> → <verbe>` — **seul** mécanisme qui départage deux voisins.
3. Portée d'invocation conservée (« par l'utilisateur ET par l'agent en autonomie »).
4. Corps = délégation courte, reframe VibeFlow, enchaînement typique. **Jamais** de logique recodée.
5. Les noms `gsd-*` n'apparaissent que dans le corps (usage interne), **jamais** dans la description.
