### Déviation assumée — les trois `plugin/*/README.md`

`scripts/check-version-sync.sh`, que le plan exige à `rc=0`, gate AUSSI l'en-tête `**Version**`
de chaque README de module (ligne `✓ en-tête Version des README de modules : 17 déclarés`). Le
bump rendait donc trois de ces en-têtes faux :

```
✗ plugin/conductor/README.md : en-tête Version v1.40.0 ≠ VERSION v1.41.0
✗ plugin/dev-orchestrator/README.md : en-tête Version v2.23.1 ≠ VERSION v2.23.2
✗ plugin/planning-core/README.md : en-tête Version v2.7.0 ≠ VERSION v2.7.1
```

Écart **créé par ce plan**, donc **fermé par lui** — application de la règle d'arbitrage déjà
suivie par `41.1-03` et `41.1-05` (qui ont fermé le compte de suites des README, 85→86→87, que
leurs suites neuves rendaient faux) : la phase ferme ce qu'elle a créé. La `files_modified` du
plan est une **rédaction** incomplète, pas un contrat : elle ne pouvait pas rendre
`check-version-sync.sh` vert en même temps qu'elle-même. Les README **racine**, la `VERSION`
racine, `plugin.json`, `marketplace.json` et le CHANGELOG racine restent **intouchés** — la
release est un geste humain hors périmètre.
