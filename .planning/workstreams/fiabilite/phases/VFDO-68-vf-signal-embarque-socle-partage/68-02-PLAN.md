## Spécification du retard (aucun analogue dans le socle, 68-PATTERNS § 3)

- Toute commande git du module passe par `sh('git', [...GIT_SUR, '-C', <arbre>, ...])` (même `sh()` borné que `who.mjs` :
  `execFileSync`, timeout 10 s, stderr muet) et n'emploie que des sous-commandes qui ne lisent ni l'index ni l'arbre de
  travail : `worktree list --porcelain`, `symbolic-ref`, `show-ref --verify`, `rev-list --count`, `rev-parse`.
- `brancheBase` : `symbolic-ref --quiet --short refs/remotes/origin/HEAD` privé de `origin/` ; sinon `main` si
  `show-ref --verify --quiet refs/heads/main` réussit ; sinon `null`.
- `retard` : `main` = entier de `rev-list --count HEAD..<base>` lancé dans l'arbre (`null` si `base` est `null` ou la sortie
  n'est pas un entier) ; `origin` = idem contre `origin/<base>` seulement si `show-ref --verify --quiet
  refs/remotes/origin/<base>` réussit ; `fetchAgeS` = secondes entières entre `now` et la date de modification de
  `<commonDir>/FETCH_HEAD`, `null` si le fichier manque.
- `phaseActive` : règle P68-PL-04 (registre de 68-01) ; `phases` dans l'ordre de la feuille de route, chacune avec
  `avancement` ; rend `{ key, n, nom: name, etat: avancement.etat }`.
- `nettoie(s, n)` : retire les caractères de contrôle (C0, DEL, C1), applique `masque` de `vf-cockpit-lecture.mjs`, borne à
  `n` caractères ; toute chaîne d'arbre ou de branche qui sort du socle passe par elle.
