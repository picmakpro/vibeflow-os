## Hypothèses explicites (non couvertes littéralement par CONTEXT.md, dérivées et assumées ici)

**H-1 — Les slugs de FICHIERS sont identiques en FR et EN, et rédigés en français.**
D-05 fixe des slugs de **dossiers** identiques FR/EN, et ils sont en français (`01-demarrer`,
`04-cycle-de-dev`…). D-01 conséquence 2 exige que le sélecteur de langue soit « miroir du chemin,
`fr`↔`en` au 2ᵉ segment », et D-01 réduit la sonde de parité à « un `diff` de deux `find` ». Ces deux
exigences imposent mécaniquement des noms de fichiers identiques dans les deux arbres. Par cohérence
avec les dossiers déjà tranchés, les slugs de fichiers sont donc **en français dans les deux
langues** ; seul le **contenu** et les **titres affichés** changent. Le titre EN de chaque page vit
dans `toc.yml` (clé `en:`), jamais dans le nom de fichier.

**H-2 — `toc.yml` est un sous-ensemble YAML plat, volontairement parsable en bash pur.**
D-03 impose le nom `toc.yml` mais aucun parseur YAML n'est disponible en dépendance de ce repo pour
un outil local. Le schéma retenu (voir `<artifact_specs>`) est du YAML valide restreint : indentation
à 2 espaces, aucune ancre, aucune valeur multi-ligne, une clé par ligne — `awk`/`sed` suffisent.

**H-3 — Le gate `check-manual.sh` sort légitimement en 1 à la fin de ce plan.**
Aucune page n'existe encore ; D-13 exige que le gate échoue sur une découverte vide. Ce n'est **pas
un défaut** : c'est le comportement demandé. La preuve de bon fonctionnement du gate à ce stade se
fait sur **arbres de fixture** (task 3), pas sur le manuel réel. À partir de la vague 2, le gate doit
sortir en 0 sur le manuel réel.

### Schéma de `manual/toc.yml` (H-2)

```yaml
# manual/toc.yml — séquence canonique du manuel (D-03).
# INVARIANT : n'inscrire une page qu'APRÈS l'avoir écrite dans LES DEUX langues.
# Un `path` inscrit sans fichier fr ET en fait échouer manual/.tools/check-manual.sh.
themes:
  - dir: 01-demarrer
    fr: Démarrer
    en: Getting started
  - dir: 02-concepts
    fr: Comprendre
    en: Core concepts
pages:
  - path: 01-demarrer/prerequis.md
    fr: Prérequis
    en: Requirements
  - path: 01-demarrer/installation.md
    fr: Installer VibeFlow
    en: Installing VibeFlow
```

Contraintes de forme : indentation à 2 espaces, une clé par ligne, aucune ancre, aucune valeur
multi-ligne, aucun bloc `|`/`>`. L'ordre des entrées `pages:` **est** l'ordre de lecture. Le bloc
`themes:` liste **uniquement** les thèmes ayant au moins une page inscrite.

### Marqueurs de blocs générés

Trois blocs, tous délimités par un couple de commentaires HTML, tous réécrits par `build-nav.sh` et
jamais à la main :

```
<!-- vf-manual:lang -->        …sélecteur de langue…       <!-- /vf-manual:lang -->
<!-- vf-manual:nav -->         …bandeau prev/sommaire/next…<!-- /vf-manual:nav -->
<!-- vf-manual:sommaire -->    …liste de liens du thème…   <!-- /vf-manual:sommaire -->
```

- `vf-manual:lang` : présent en tête de **chaque** page et de chaque `README.md` de langue.
  Contenu FR : `**Français** · [English](../../en/<dir>/<slug>.md)`.
  Contenu EN : `[Français](../../fr/<dir>/<slug>.md) · **English**`.
  Pour un `README.md` de langue, le chemin est `../en/README.md` / `../fr/README.md`.
- `vf-manual:nav` : présent en pied de **chaque** page (jamais dans les README).
  Forme FR : `[← Précédent](../<dir>/<slug>.md) · [↑ Sommaire](../README.md) · [Suivant →](../<dir>/<slug>.md)`.
  Forme EN : `[← Previous](…) · [↑ Contents](../README.md) · [Next →](…)`.
  Le chemin d'une page voisine est **toujours** de la forme `../<dir>/<slug>.md`, y compris pour une
  sœur du même dossier — forme unique, donc toujours correcte. La première page n'a pas de segment
  `← Précédent` ; la dernière n'a pas de segment `Suivant →`.
- `vf-manual:sommaire` : présent dans `manual/fr/README.md` et `manual/en/README.md` uniquement.
  Contenu : pour chaque thème de `toc.yml` dans l'ordre, un `### <titre du thème>` suivi de la liste
  `- [<titre de page>](./<dir>/<slug>.md)` de ses pages.

### Contrats de sortie des deux scripts

`build-nav.sh [ROOT]` — `ROOT` par défaut = le dossier parent de `.tools/`. Réécrit les trois blocs
sur tout l'arbre. Sort 0 si tout est réécrit, 1 si `toc.yml` référence un fichier absent ou si un
fichier de page ne porte pas ses marqueurs. Idempotent : deux exécutions successives laissent l'arbre
strictement identique.

`check-manual.sh [ROOT]` — sept contrôles, sortie `✓`/`✗` par contrôle, `exit 1` dès le premier
échec constaté (tous les contrôles sont exécutés, le code de sortie est agrégé) :

| ID | Contrôle | Échec si |
|----|----------|----------|
| C0 | verdict non vide (D-13) | 0 page `.md` découverte sous `<ROOT>/fr` **ou** 0 entrée `- path:` dans `toc.yml` (les entrées sont indentées de 2 espaces : compter sur `^[[:space:]]*- path:`) |
| C1 | isomorphisme fr/en (D-01) | `find` relatif de `<ROOT>/fr` ≠ `find` relatif de `<ROOT>/en` |
| C2 | toc.yml ↔ disque (D-03) | une entrée `- path:` sans fichier dans les 2 langues, **ou** un `.md` sous `<ROOT>/<lang>/NN-*/` absent de `toc.yml` |
| C3 | liens relatifs (D-01) | un lien markdown relatif d'un fichier du manuel ne résout pas vers un fichier existant (ancres `#…` et URL `http…` ignorées) |
| C4 | bandeau ↔ toc (D-03) | l'arbre diffère de ce que `build-nav.sh` produit sur une copie temporaire |
| C5 | zéro version en dur (D-11) | une ligne hors bloc de code contient un motif `vX.Y.Z` et ne porte pas `<!-- manual-allow-version -->` |
| C6 | format de page (D-04) | une page dépasse 300 lignes **ou** porte plus de 3 titres H2 ; avertissement (sans échec) hors de la fourchette 100-200 lignes |
