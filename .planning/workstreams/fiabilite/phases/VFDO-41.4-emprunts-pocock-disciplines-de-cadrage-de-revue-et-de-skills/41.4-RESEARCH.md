## Summary

Le cadrage est verrouillé (16 décisions) ; cette recherche mesure les faits du dépôt sur lesquels les plans s'appuieront. Les huit exigences se répartissent en trois familles de travail de nature différente : (1) **doctrine en prose** (POCK-01, 02, 03 et la face « pilotage » de POCK-04) — pas de gate machine possible pour le jugement, donc le seul garde réalisable est un test statique d'ancres avec mutation ; (2) **gates à étendre** (POCK-06 dans `check-mission-exit.sh` E3, POCK-07 dans `check-skills.sh` + une étape CI neuve, POCK-08 dans `check-ajout-retrait.sh`) — chacun a une suite à mutants qui épingle des lignes exactes ; (3) **script de rétro** (POCK-05, `detect-promotions.sh`).

Cinq résultats changent le plan par rapport au CONTEXT. **(a) POCK-07 : la liste des skills `disable-model-invocation: true` dérivée par les arêtes est vide au sens strict** — sur 26 skills, 17 ont un appelant machine (commande, préchargement, routage d'un agent) ; les 9 autres sont `vf-dev` (verrouillé model), `software-architecture` et `vf-business/content/growth` (déclencheurs en langage naturel), `vf-mobile-test` (référencé par prose depuis un worker sans outil Skill) et 3 gabarits doc-only (`agent-density-auditor`, `debugger`, `safe-execute`). Aucun n'est à la fois « effet de bord lourd » et incontestablement sans appelant : **à remonter au manager** (Q1). **(b) D-14 cite des versions déjà livrées** : `dev-orchestrator v2.26.0`, `conductor v1.46.0`, `consolidator v1.10.0` sont les versions COURANTES (release v2.68.0) ; les bumps sont v2.27.0 / v1.47.0 / v1.11.0. **(c) Un fichier de suite neuf casse `check-version-sync`** (le README racine cite « 98 suites » = le nombre réel) : étendre les suites existantes. **(d) Deux `gsd-code-reviewer` parallèles écrivent le même `REVIEW.md`** sauf si chaque brief passe un `review_path` distinct (champ de config lu dans l'agent installé). **(e) `.github/` et la baseline du budget d'instructions sont sous CODEOWNERS `@picmakpro`** : l'étape CI neuve (POCK-07) et toute hausse de baseline exigent la revue de Willy.

**Primary recommendation :** quatre lots de fichiers disjoints en vague 1 (gates conductor ; consolidator ; doctrine head/manager ; docs-flow + scaffold), la revue/PR en vague 2 (elle partage `mission-flow.md` et `mission-contracts.md` avec la doctrine), puis une vague finale unique pour les frontmatters des 26 skills (après que le gate existe), les bumps de modules, BACKLOG/REQUIREMENTS et le dogfood `check-ajout-retrait --strict`. Déclarer la classe par un champ VibeFlow explicite **et** vérifier sa cohérence avec le champ natif ; ne poser `disable-model-invocation: true` sur rien tant que le manager n'a pas tranché Q1.

### Pattern 1 : étendre la chaîne `check_file` de `check-skills.sh` [VERIFIED: plugin/conductor/scripts/check-skills.sh:573-591]
**What :** `check_file(rel, text)` enchaîne des appels uniques, un par invariant : `errors.extend(valider_marqueurs(rel, fm))` (l.586) puis `warnings.extend(detecter_derive(rel, fm, lignes_de_portee(text)))` (l.587). Chaque appel est la cible d'un mutant de la suite (MUT-S*, MUT-DR*). Ajouter les contrôles de classe comme **deux appels uniques** (un vers `errors`, un vers `warnings` pour la dette Type 1), jamais fusionnés.
**Contraintes mesurées :**
- Champs VibeFlow en dur : `VIBEFLOW_SKILL_FIELDS = {"vf-nature", "ecrit", "vf-rubrique-juge", "vf-gate-bloquant",` / `"vf-livrable-tiers", "vf-couche-qualite"}` (l.191-192). Un champ neuf doit y entrer sinon avertissement « champ inconnu », ET entrer dans `ALLOWED_PROPERTIES` de `plugin/skill-creator/skills/skill-creator/scripts/quick_validate.py` (l.45) — la suite `test-quick-validate.sh` test 4 rougit sinon (parité). [VERIFIED: quick_validate.py:42-46 ; test-quick-validate.sh:4]
- `disable-model-invocation` est déjà natif connu : `"disable-model-invocation", "user-invocable", "allowed-tools", "disallowed-tools",` (manifeste l.48). MAIS `ALLOWED_PROPERTIES` de `quick_validate.py` (l.42) ne contient PAS `disable-model-invocation` : un skill produit par skill-creator avec ce champ serait refusé.
- Le gate est GÉNÉRIQUE : l'exclusion des gabarits doc-only est portée par l'invocation, jamais par un nom de module en dur (en-tête l.~45-52).
- Sorties : 0 conforme / 1 non conforme / 3 INDÉTERMINÉ ; `--hook` traduit 3 → 0. Un nouveau mode « arêtes » doit rendre 3 (bruyant) si la racine d'arêtes est absente ou vide — jamais un vert à vide (patron F13).
- Tout texte issu d'un frontmatter passe par `esc()` (T-43-04) — jamais réinjecté brut.
**Recommandation :** option `--callers-root=<dossier>` (défaut absent = contrôles d'arêtes non joués, pour que T4/T32 « arbre réel » par module, qui appellent `--skills-dir=<module>`, restent verts). Racine d'arêtes = un dossier contenant `commands/`, `*/AGENT.md`, `*/agents/*.md` (source : `plugin/`) ; chez un lab installé, `.claude/`. Étape CI : `--skills-dir=plugin --callers-root=plugin --strict` — mesuré : `--skills-dir=plugin` juge 26 SKILL.md, rc 0, 32 warnings « derive » (non bloquants). [VERIFIED: exécution cette session]

### Pattern 2 : grammaire du trailer `Ajout-Retrait:` [VERIFIED: plugin/conductor/scripts/check-ajout-retrait.sh:15-34, 175-209]
Forme : `Ajout-Retrait: <chemin|ADR-NNN|CLAUDE.md> — <retrait | aucun : justification>` ; séparateur ` — ` ou ` - ` ; retrait nommé ≥ 10 caractères non blancs, ou `aucun :` suivi de ≥ 10 ; motif sans virgule, glob admis seulement dans le dernier segment avec ≥ 6 caractères littéraux. Le découpage se fait au PREMIER séparateur (`motif="${value%%"$sep"*}"; reste="${value#*"$sep"}"`). Sortie : ligne `decouverte:` puis `AJOUT-COUVERT` / `AJOUT-NON-COUVERT` / `AJOUT-COMPENSE` / `MARQUEUR-MAL-FORME`, verdict `COUVERT` / `NON-COUVERT` / `RIEN-A-JUGER`. Codes : 0 hors `--strict` ; `--strict` : 1 non couvert, 2 NON VÉRIFIABLE, 64 usage.
**Pour POCK-08 :** (i) un segment `défaillance :` en fin de `reste` (3ᵉ segment) ; extraire par la DERNIÈRE occurrence pour ne pas casser un retrait contenant déjà ` — ` ; (ii) la longueur ≥ 10 s'évalue sur la part AVANT le segment, sinon un « aucun : » vide passe grâce à une défaillance longue ; (iii) accepter la graphie ASCII `defaillance` (borne ASCII déjà posée pour le séparateur) ; (iv) forme minimale de la défaillance : ≥ 10 caractères non blancs + une date ISO ou un SHA (précédent G-1 : « mot-clé, au moins deux virgules puis une date ISO », verification de forme jamais de véracité) ; (v) nouveau genre `skill` dans l'awk des ajouts (statut A, motif `plugin/**/SKILL.md`, compensation par un SKILL.md supprimé), clé = chemin du SKILL.md.

### Pattern 3 : sous-contrôle « corps de PR » dans E3 [VERIFIED: plugin/dev-orchestrator/scripts/check-mission-exit.sh:298-343]
E3 lit `E3_PR_JSON="$(cd "$ROOT" && gh pr view --json state 2>/dev/null)"` (l.328) puis `jq -r '.state // empty'`. Codes du gate : **3 = SAIN, 0 = manque nommé, 4 = INDÉTERMINÉ, 64 = usage** (précédence 64 > 4 > 0 > 3). Étendre à `--json state,body` ; trois issues pour le sous-contrôle : section présente et conforme → sain ; PR lisible mais section absente/incomplète → `manque` (message `[E3] …`) ; clé `body` absente du JSON ou non-chaîne → `indet` (jamais un manque par défaut, jamais un sain). Distinguer corps vide (`""` → manque) de `null`/absent (indet) : `jq -r '.body // empty'` écraserait la distinction — utiliser un test de type. [ASSUMED : forme exacte de la section ; à fixer par le planner contre `mission-contracts.md`, proposition : un titre `## Merge-danger call`, une ligne `Porte : sens unique|double sens` (énumération fermée), une ligne `Rayon d'explosion : <≥ 10 caractères>`.]
Les replis déjà écrits (aucune PR lisible, `gh` absent, non authentifié) restent INDÉTERMINÉS : le contrôle de corps ne s'applique que si la PR est lue. Le corps de PR est une donnée non fiable (contenu GitHub) : parse par `jq`/awk, jamais d'interpolation shell ni d'`eval`, et toute valeur rendue sur la sortie est échappée.

### Pattern 4 : revue à deux axes [VERIFIED: plugin/dev-orchestrator/agents/vf-reviewer.md ; mission-contracts.md ; mission-flow.md Pattern C]
Le bloc typé actuel est `{ "statut": "passed|gaps_found|human_needed|blocked", "findings": [{ "severity": "bloquant|majeur|mineur", "action": "auto-fix|no-op|ask-user", "ref": "fichier:ligne" }], "noeuds_debloques": [] }` (vf-reviewer.md, section Retour). Même patron pour `axes` : champ optionnel frère, `statut` global = conjonction des deux (compatibilité arrière : un manager qui ne lit que `statut` continue de piloter juste). Le schéma vit dans `mission-contracts.md` (une voix) ; `vf-reviewer.md` renvoie ; la règle de pilotage tient en UNE phrase dans `mission-flow.md` Pattern E §2, **hors** de la « table de pilotage » (foyer unique que T24 épingle).

### Pattern 5 : doctrine en prose (POCK-01, 02, 03) — garde réalisable
Une règle de jugement n'est pas un gate (`software-architecture` : « un garde-fou non exécuté par la machine n'existe pas » ; `audit-architecture` : « un audit non forcé est un avis »). Le garde honnête : un test statique d'ANCRES dans `test-dev-orchestrator.sh` (présence des éléments de l'arbre dans `head-governance.md` §3, de la discipline dans `mission-flow.md` §Pattern F, du renvoi dans `head-governance.md`) avec une mutation par ancre (le patron T24/T30 : ablation chirurgicale du token, l'assertion doit rougir). ### Pattern 6 : `nature: mecanique|jugement` dans `detect-promotions.sh` [VERIFIED: plugin/consolidator/scripts/detect-promotions.sh]
Sortie JSON construite par `printf` : `{"type": "operational_single", "lrn_id": …, "title": …, "category": …, "rule_slug": …, "confidence": 0.85}` et `{"type": "frequency_cluster", "category": …, "lrn_ids": …, "rule_slug": …, "confidence": 0.7}`. Le tri se fait dans un heredoc Python NON quoté (`<<PYEOF`) : `$` et backticks y sont interprétés par bash (Pitfall 4). Mots-clés opérationnels existants : `toujours, jamais, eviter, forcer, obligatoire, interdire, prefer, always, never, avoid, must`. Ajouter `"nature"` aux deux `printf` (le champ doit être calculé avant l'affichage : étendre la ligne `ID|titre|catégorie` du bloc OPERATIONAL et la ligne du cluster). Heuristique (discrétion du planner) [ASSUMED] : mécanique = le texte désigne un motif syntaxique, une API/commande bannie, un chemin ou un nom de fichier, un format (indices lexicaux : extension de fichier, `console.log`, `import`, `lint`, `commit`, `chemin`, `regex`, `fichier`) ; jugement = tout le reste (défaut `jugement` : ne jamais proposer un check à tort). Test : `test-consolidator.sh` T6 n'asserte que `"lrn_id": "LRN-002"` ; ajouter T6b/T6c sur une fixture **construite dans le test** (ne pas modifier `fixtures/LEARNINGS-mini.md`, partagée par T1-T5 et T7).

### Anti-Patterns to Avoid
- **Un vert à vide** : arêtes non calculables (racine absente, 0 commande, 0 agent) = INDÉTERMINÉ, jamais conforme.
- **Poser `disable-model-invocation: true` pour verdir** : le gate doit RECONNAÎTRE la liste, pas la fabriquer ; poser la valeur d'un skill à arêtes réelles casse le déclenchement en langage naturel et le préchargement (voir Citation docs).
- **Recopier la doctrine** dans l'agent (ADR-030, T33 interdit `gh pr create` / `git worktree add` recopiés dans `GSD-PIPELINE.md` §1 et §6).
- **Un fichier de suite neuf** (Pitfall 8).

## Common Pitfalls

### Pitfall 1 : les mutants de suite remplacent des LIGNES EXACTES
**What goes wrong :** `test-check-ajout-retrait.sh` (MUT-1..9) et `e7_mutant` remplacent une ligne par égalité stricte (`$0 == ENVIRON["MUT_OLD_ENV"]`) ; `make_gate_mutant` exige UNE occurrence du motif. Reformater une ligne ciblée (`[ "$ok" -eq 1 ] && [ "$(charcount "$just")" -lt 10 ] && ok=0` ; `  [ "${#lit}" -ge 6 ]` ; `    l ~ /^- / { sub(/^- /, "", l); print l; next }` ; `COMMITS_LIST="$(git rev-list "${BASE}..${HEAD_SHA}" 2>/dev/null)"` …) fait passer le mutant en « NON OPPOSABLE », donc la suite rouge pour une raison étrangère.
**How to avoid :** ne pas toucher ces lignes ; ajouter des lignes à côté ; ou mettre à jour le mutant dans le même commit. Rejouer la suite après chaque édition du gate.
**Warning signs :** `NON OPPOSABLE`, `MOTIF AMBIGU OU ABSENT`.

### Pitfall 2 : le segment `défaillance :` obligatoire rend MAL-FORMÉS tous les trailers de la suite actuelle
Les cas A1, A1b, A3b, A4, A8, A11 et les fixtures MUT-1, MUT-4, MUT-7 écrivent `$TR <motif> — retire … ` sans segment. Les rendre conformes (variable `TR` + segment commun) fait partie du lot POCK-08 ; ajouter A12 (segment absent → non couvert, rc 1 sous `--strict`), A13/A14 (SKILL.md ajouté couvert / compensé), MUT-10 (segment neutralisé), MUT-11 (genre skill neutralisé). Les 39 assertions actuelles sont le plancher de non-régression.

### Pitfall 3 : le stub `gh` ne renvoie que `{"state":"OPEN"}`
`test-check-mission-exit.sh` (talons aux l.42 et 56) : tout cas « sain » passerait en INDÉTERMINÉ/MANQUE dès que E3 lit `body`. Étendre les DEUX talons et ajouter les cas c-E3b/c/d (conforme, section absente, `body` absent) ; la suite fait 62 assertions en ~51 s.

### Pitfall 4 : heredoc Python non quoté dans `detect-promotions.sh`
`python3 - <<PYEOF` (sans guillemets) : `$LEARNINGS_FILE` est interpolé volontairement ; tout `$`, backtick ou `\$` ajouté dans le code Python est lu par bash. Écrire la heuristique sans `$`/backtick, ou passer par une variable d'environnement.

### Pitfall 5 : deux `gsd-code-reviewer` parallèles, un seul `REVIEW.md`
Sans `review_path` distinct par brief, les deux écrivent `{phase_dir}/{phase}-REVIEW.md` (écrasement/course). Chaque dispatch doit passer son chemin (Standards / Spec) et `vf-reviewer` doit enregistrer DEUX sous-agents au registre (`driver-lock.sh register …` ×2, `close` ×2) — la ligne actuelle n'en prévoit qu'un. L'axe Spec exige le chemin du PLAN de l'étape dans le brief : **absent ⇒ `axes.spec.statut` ≠ `passed`** (jamais un vert par défaut). Coût : double dispatch par revue ; le régime allégé (Pattern E §3) interagit (Q6).

### Pitfall 6 : épingles de prose dans `test-dev-orchestrator.sh` (6993 lignes, 229 assertions, ~40 s)
T24 (mapping `human_needed`/`gaps_found` dans la table de pilotage de `mission-flow.md`, formes F1/F2), T25 (interdit `--auto`/non-interactif prescrit sur une brique Cadrage ou Plan, balayage de `$TEAM_AGENTS` + `references/*.md`), T27 (ancres de la table), T30 (section `## Contrat de checkpoint amont` jusqu'à `## Étage revue` de `mission-contracts.md` ; `vf-dev-manager.md` : `verdicts` > 2 occurrences dont une sous `## Rapport de mission`), T33 (`GSD-PIPELINE.md` §1/§6 ne recopient jamais `gh pr create`), T37 (aucun `gsd-*` dans la colonne Mind de `head-governance.md` §1), T38 (aucune prescription de `Task(vibeflow-head)`), T22 (`docs-flow.md` : `gsd-docs-update`, `--verify-only`, `ADR-031`, `^## Interdits`, `gsd-map-codebase`, `gsd-extract-learnings`, `ingestion-flow`, `check-doc-drift.sh`, ligne `--force`, frontière `vibeflow-os`). **Règles d'écriture :** ne jamais écrire « cadrage … `--auto` / non-interactif » dans le texte neuf ; ne jamais prescrire une commande `gsd-*` dans `head-governance.md` (le head gouverne, ne lance pas GSD) ; ne pas renommer ni déplacer les titres `##` cités ; ne pas toucher la table de pilotage. Les ajouts d'assertions vont en T39+ à la fin du fichier (avant la ligne `== résultat`), un seul plan écrivain.

### Pitfall 7 : `quick_validate.py` et la marge de `skill-creator/SKILL.md`
`ALLOWED_PROPERTIES` n'a ni `disable-model-invocation` ni un champ de classe neuf ; `skill-creator/SKILL.md` est à **493 lignes** (plafond ADR-029 : 500, gate `check-instruction-budget`). Un champ de classe → ajout dans `quick_validate.py` (+ bump `skill-creator` v1.1.2) mais **pas** d'instruction supplémentaire dans le SKILL.md au-delà de ~6 lignes.

### Pitfall 8 : tout fichier `*/tests/test-*.sh` neuf casse `check-version-sync`
Point 9 du gate : `suites_real="$(find "$ROOT/plugin" "$ROOT/scripts" -path '*/tests/test-*.sh' 2>/dev/null | grep -c .)"` doit égaler le premier « N suites » des deux README racine — mesuré **98 = 98**. Les README racine sont partagés avec la release (geste humain). **Étendre les suites existantes**, aucune suite neuve.

### Pitfall 9 : fan-out des bumps de module
Chaque module touché : `plugin/<mod>/VERSION`, `plugin/<mod>/module.json` (`.version`), `plugin/<mod>/CHANGELOG.md`, et l'en-tête `**Version**` de `plugin/<mod>/README.md` (point 8 de `check-version-sync`, les 17 modules en déclarent un). `plugin/installer` n'a ni `module.json` ni `VERSION` (aucun bump). Voir la matrice.

### Pitfall 10 : `check-machine-paths` balaie TOUS les fichiers suivis (1818 mesurés)
Un chemin absolu de machine dans un plan, une recherche ou un rapport de mission rougit la CI. Chemins relatifs uniquement.

### Pitfall 11 : budget d'instructions (G-1) et marqueurs
`check-instruction-budget.sh` compte, dans le body des seuls fichiers `plugin/*/agents/*.md` + `plugin/*/AGENT.md`, les lignes contenant `MARKER_RE='jamais|toujours|ne .* pas|doit|must|never|always|interdit|obligatoire'` (l.133) plus les puces sous un titre de règles. Baselines mesurées : `vf-reviewer.md 79 9`, `vf-dev-manager.md 250 46`, `dev-orchestrator/AGENT.md 209 33`. Le texte de POCK-04 écrit dans `vf-reviewer.md` (« jamais re-rankés », « doit ») peut dépasser 9 : écrire le fond dans `mission-contracts.md` (référence, non budgétée) et ne laisser dans l'agent qu'un renvoi sans marqueur ; sinon la hausse de baseline exige, dans le commit qui la porte, une citation d'arbitrage `arbitrage Samuel, AskUserQuestion session principale, 2026-10-06` (G-1 : mot-clé, ≥ 2 virgules, date ISO) ET la revue `@picmakpro` (CODEOWNERS : `/.planning/instruction-budget-baselines.tsv`). `vf-dev-manager.md` : ne pas dépasser 250 lignes — le resserrement de la l.23 se fait à nombre de lignes constant.

### Pitfall 12 : surface de G-2 (`Gate-Touche:`)
Surface = `plugin/conductor/scripts/check-*.sh`, `scripts/check-*.sh`, leurs suites (`plugin/conductor/scripts/tests/test-*.sh`, `scripts/tests/test-*.sh`), `.github/workflows/ci.yml`, `scripts/hooks/`. Une phase qui touche `check-skills.sh`, `check-ajout-retrait.sh`, leurs deux suites et `ci.yml` exige **un trailer par chemin** (`Gate-Touche: <chemin> — <raison ≥ 10 caractères>`, motif sans virgule). `check-mission-exit.sh` est HORS surface par arbitrage du 2026-09-17, mais le `CLAUDE.md` demande le trailer pour tout gate modifié : le poser quand même.

### Pitfall 13 : péremption du manifeste daté
`check-agents-manifest.json` : `"valide_jours": 30`, listes `verifie_le` 2026-09-23 (six) et 2026-09-26 (`champs_frontmatter_skills`). La CI passe `--manifest-freshness=strict` (étapes `check-agents`) : **rouge à partir du 2026-10-23** si le manifeste n'est pas rafraîchi (relire la source, comparer, re-dater — jamais une date seule). Une PR de cette phase mergée après cette date échoue pour une raison étrangère.

### Pitfall 14 : « famille savoir » dit « jamais pendant »
`docs-flow.md` : la famille savoir « se déclenche **après** une vérification ou une clôture d'étape — jamais pendant ». Le glossaire est tenu PENDANT le cadrage (avant). L'adosser sans réserve contredit la section ; formuler une exception explicite (le glossaire est le seul objet de cette famille alimenté pendant le cadrage). Terrain voisin de la Phase 48 de Willy (pont mémoire) : ne pas empiéter.

### Pitfall 15 : Windows (`windows_enforce: true`)
Pas de `sed -i` sans suffixe, pas de `grep -P`, pas d'`date -I`, mêmes précautions que `hook_exit` et `PYBIN`. `rtk` et le hook de garde du worktree faussent les mesures `grep`/`find` : utiliser `rtk proxy`.

### Pitfall 16 : Type 1 et `agents/openai.yaml`
Le Type 1 copie le SKILL.md SEUL (`vf_place_file "$module_dir/SKILL.md" "$TARGET_ROOT/skills/$mod/SKILL.md"`, l.2292) ; un `plugin/<mod>/agents/` est lu par la boucle Type 3b (l.2314-2318 → `agents/`) et par la CI `check-agents` sur `plugin/*/agents` : y poser `openai.yaml` le ferait installer comme AGENT et linter comme tel. Seul le Type 2 (`vf_place_tree "$skill_dir" "$TARGET_ROOT/skills/$skill_name"`, l.2302) transporte `skills/<nom>/agents/openai.yaml`. [VERIFIED: vibeflow-update.sh:2290-2322]

### Pitfall 17 : textes périmés rencontrés (D-15 les ferme s'ils sont touchés)
