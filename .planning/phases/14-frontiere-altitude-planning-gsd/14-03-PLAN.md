# Plan 14-03 — Fin de la double injection au démarrage

## But

Sur un lab dev, `SessionStart` empile aujourd'hui `gsd-session-state.sh` **et**
`check-planning-state.sh` **et** `planning-context.sh` : deux digests de la même réalité, coût
contexte payé deux fois. Faire taire les nôtres quand GSD couvre déjà le projet — **sans** changer le
comportement par défaut des scripts, qui servent aussi en manuel et au `/checkpoint`.

Complète le critère de succès 3 du ROADMAP. Vague 2 : dépend de 14-01 (le détecteur doit exister).

## Exigences couvertes

ALTI-03.

## Tâches

Le **code exact** (5 cas de test + les deux patchs) est dans la **Task 2** du plan détaillé :
`docs/superpowers/plans/2026-07-25-rescope-vf-planning-gsd.md`. En TDD :

1. Ajouter les 5 cas à `tests/test-planning-hooks.sh`, **avant** le bloc de résumé `== résultat :`.
   Réutiliser les variables de chemin et les compteurs `PASS`/`FAIL` déjà définis dans ce fichier —
   ne pas en introduire de nouveaux.
2. Lancer → doivent échouer les cas A, C, D.
3. Patcher `check-planning-state.sh` : variable `DEFER_TO_GSD=0`, cas d'argument, puis délégation au
   détecteur **après** `say()` et **avant** le test d'existence de `$PLANNING_DIR`.
4. Patcher `planning-context.sh` : idem, mais la condition inclut `[ ! -f "$INDEX_FILE" ]` — l'altitude
   lab l'emporte sur le retrait.
5. Câbler `--defer-to-gsd` dans `hooks.json` (2 commandes sur 3) + citer ADR-054 dans la `description`.
6. Relancer les tests, non-régression complète, commit.

## Risques / points d'attention

- **Le piège principal** : changer le comportement par défaut. Le cas de test B existe précisément pour ça —
  sans flag, le script doit continuer à parler. Ne jamais déplacer la détection avant la lecture des arguments.
- **`planning-context.sh` ignore silencieusement les arguments inconnus** (`*) shift ;;`), contrairement à
  `check-planning-state.sh` qui sort 64. Conséquence : sur ce script, un flag mal orthographié ne lève aucune
  erreur — d'où l'importance du cas de test C, qui vérifie l'effet et non l'acceptation du flag.
- **Ordre d'insertion dans `planning-context.sh`** : la détection doit venir **après** la définition de
  `INDEX_FILE`, sinon la condition `[ ! -f "$INDEX_FILE" ]` teste une variable vide et le lab à compartiments
  perd son injection (régression silencieuse, non couverte par les tests existants — c'est le cas D).
- **Ne pas toucher au `Stop` guard.** C'est l'exception assumée d'ADR-054 ; toute modification sort du scope
  de ce plan.
