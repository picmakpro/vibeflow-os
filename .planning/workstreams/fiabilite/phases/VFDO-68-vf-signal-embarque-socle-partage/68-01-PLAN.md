## Interface de l'avancement, version 2 (contrat figé par ce plan, lu par 68-03)

- Objet : `{ version: 2, etat, plans: { faits, total }, correctifs, mission, reste }` ; `mission` = `{ nom, etat, vie }` ou
  `null` ; `etat` de mission ∈ `ETATS_MISSION` = `['running', 'abandonnee', 'inconnu', 'failed', 'done', 'ready']` ;
  `vie` = `{ tenu, stale, progressAgeS, ttl }` (verrou lu ; verrou absent : `tenu: false`, le reste `null`) ou `null`
  (source des verrous illisible, P68-D-23).
- Verrou d'une mission (P68-D-22) : `vieDe({ ws, phase }, verrous)` ; `ws` et `phase` (= `n`) sont lus dans l'objet de la
  phase `phases.get(cle)`, `cle` venant de `rattacherMission` (qui rend `{ cle, regle }`, sans numéro : champ `phase`, sinon nom
  `MISSION-<n>`, sinon dossier de phase) ; l'entrée cherchée est celle de `scope` `phase`, mêmes `ws` et `phase` comparés en
  chaîne normalisée (`normPhase`, exporté par `vf-cockpit-vie.mjs` : segments passés par `Number`, `069` = `69`) ; cascade (P68-D-26) : (1) les entrées de phase présentes (la vive si plusieurs, par exemple `069` et `69`), (2) sinon l'entrée de
  `scope` `compartiment` de `ws` si elle est présente, (3) sinon `tenu: false` ; le verrou de phase, même périmé, passe avant le
  repli ; `phase` du verrou est une chaîne (type gardé) ; lab plat : le verrou unique ; DAG hors phase : compartiment, sinon de
  dépôt (P68-PL-02).
- `etatMission(nodes, vie)` : si un nœud est `running` : `running` quand `vie` est `undefined` (appelant qui ne lit pas les
  verrous) ou `estVivante(vie)` ; `inconnu` quand `vie` est `null` ; `abandonnee` sinon ; puis `failed`, `done`, `ready`
  comme en version 1.
- `estVivante(vie)` : vrai si `vie.tenu && vie.stale === false`, ou si `progressAgeS` et `ttl` sont des nombres et
  `progressAgeS < ttl`.
- `reste` (vérifié au tour de révision, 2026-11-03, contre `vf-cockpit-avancement.mjs` de `phase-69b` à `dfeb37f7`) : pour une
  phase `a-faire` sans fichier de recette, la 69 livre `["verification", "cloture"]` (P69-D-07, lecture littérale). Aucun plan de
  la 68 n'affiche, n'émet autrement que verbatim (`phases[].avancement`, 68-03) ni ne teste de valeur de `reste` : rien à
  aligner ; 68-03 le sérialise tel quel et ne le recalcule pas.
- L'état de phase `en-cours` par mission ne compte que les missions `running` (ni une mission `abandonnee`, ni une mission
  `inconnu` ne gardent leur phase en cours). `LIBELLES_MISSION` : `running` « en cours », `abandonnee` « abandonnée,
  nœuds non refermés », `inconnu` « état inconnu », `failed` « en échec », `done` « faite », `ready` « prête ».
