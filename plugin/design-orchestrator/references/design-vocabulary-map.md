# Table de traduction de vocabulaire — outils design → VibeFlow

> **Rôle** : référence consultée par `vibeflow-design` et par les verbes `/vf-design` et
> `/vf-sketch` pour **reframer toute sortie** avant de la présenter à l'utilisateur.
>
> **Iron Law** : *l'utilisateur ne lit jamais un nom d'outil design brut — il ne parle que VibeFlow.*

---

## Table

| Terme outil / interne | Terme VibeFlow (exposé) |
|---|---|
| `ui-ux-pro-max` / design intelligence base | référentiel UX (interne — ne pas nommer) |
| `frontend-design` | direction créative (interne — ne pas nommer) |
| `impeccable` / craft commands | atelier de craft (interne — ne pas nommer) |

| Visual Companion | maquette comparative |

| a11y | accessibilité |
| noms bruts des plugins de la chaîne design | (plomberie interne — JAMAIS exposé) |

---

## Règles d'usage

1. **Aucune fuite de plomberie design** : ne jamais prononcer le nom d'un plugin design brut.
2. **Reframe systématique** : toute sortie d'un outil design traverse cette table avant présentation.
3. **Conserver le français** : le projet est francophone — la sortie utilisateur l'est aussi.
4. **Cohérence** : même terme VibeFlow d'une sortie à l'autre (pas de synonymes improvisés).
5. **Périmètre : la chaîne design uniquement.** Le vocabulaire GSD (`gsd-*`) peut apparaître tel
   quel côté dev — le reframe dev est abandonné (spec 2026-07-25) ; le design, lui, garde ses
   propres termes.
