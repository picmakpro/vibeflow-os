## Mesures du planning (code présent, base du plan ; les témoins de la tâche 1 les rejouent)

- **Le realpath JS de Node n'est pas physique.** `fs.realpathSync` replie lexicalement les segments `..` d'une cible de lien (et de l'argument) avant de suivre les liens ; `fs.realpathSync.native` (realpath(3)) résout comme le noyau. Mesuré sur Node 26 : lien `s -> ..` posé sous `d1/d2`, lien `t` de cible `../d1/d2/s/../../..` : JS = dossier git, natif = parent du lab. Conséquence : l'oracle « fs.realpathSync de chaque lien » du mandat serait lui-même lexical ; l'oracle de G16 est le realpath natif, contrôlé par un second oracle indépendant des chaînes de caractères (l'inode que le noyau atteint en suivant le lien, comparé aux inodes des entrées réelles de la racine).
- **Même défaut dans les gardes « déjà physiques » du code présent**, mesuré avec un lien à maillon divergent (un lien interne vers un dossier moins profond, suivi de `..`) et un leurre intérieur au lab qui porte le même nom que la cible lexicale : `scan.mjs` admet le lien et lit le fichier du dehors (le contenu sort dans les pages) ; `realUnder` (lecteur du planning) dit « dedans » et la lecture suit le noyau dehors ; `verifierSortie` et `confiner` laissent passer une sortie `.vibeflow` liée hors du lab (écriture hors du lab) ; `worktreeVerifie` dit « vérifié » pour un gitfile forgé ; `gitSortant` laisse passer un gitdir ou une inclusion à maillon divergent et un lien pendant de forme quelconque dont la cible écrite reste dans le dossier git.
- **Calibrage du générateur** (400 arbres à dossier git simple, code présent) : environ 100 arbres où la forme dit dedans et le noyau dehors, 25 à 40 où la forme dit dehors et le noyau dedans, 90 à lien non résolu, 190 entièrement dedans ; le realpath JS diffère du natif sur 130 à 150 ; la règle présente se trompe sur 55 à 80 arbres (surtout : permet à tort). 400 arbres : 1,3 s. Les deux oracles ne sont jamais en désaccord.
- **Coût de la lecture des pilotes** : `git config --name-only --get-regexp` coûte 9 ms, un `git rev-parse` 10 ms. Lire les pilotes à chaque lancement double le coût de chaque lecture (13 lancements pour une lecture de l'onglet Git) : d'où le mémo de 2 s par dossier.
- **Pilotes vidés** : git brut exécute le pilote déclaré (`log -p` : textconv ; `diff` : command, qui l'emporte sur textconv ; `merge` : driver). Vidés par GIT_CONFIG_*, aucun ne s'exécute ; avec `--no-ext-diff --no-textconv`, `log -p`, `diff`, `diff-tree`, `status` rendent 0 ; sans ces options, un textconv ou une commande vidés font échouer `log -p` et `diff` (code 128) sans rien exécuter. Les options de lecture sont insérées juste après la sous-commande : un argument qui les suit les annule (mesuré : `log -p -1 --no-ext-diff --no-textconv --textconv` lance le textconv, `diff HEAD~1 --no-ext-diff --no-textconv --ext-diff` lance la commande) ; `stash show -p` ne lance aucun pilote (mesuré), ce n'est donc pas un témoin ; un alias déclaré s'exécute sous toute sous-commande inconnue (mesuré en git brut).

## Interface exportée pour 79-13 (amendement A23)

Nom : `cheminPhysique`. Module : `plugin/cockpit/scripts/vf-cockpit-git-sortant.mjs` (export nommé), copie octet pour octet dans `plugin/cockpit/skills/cockpit-moteur/scripts/lib/vf-git-sortant.mjs`. Signature : `cheminPhysique(chemin, { plusProcheParent = false } = {})` rend une chaîne (chemin absolu physique, liens résolus par le noyau) ou `null`.
- Valeur non chaîne, vide ou contenant un octet nul : `null`. Chemin relatif : pris relativement au dossier courant par concaténation, sans normalisation.
- Mode strict : realpath natif ; tout échec rend `null` (jamais la forme écrite).
- `plusProcheParent: true` (cible d'un fichier supprimé) : sur ENOENT seulement, remonte au plus proche parent qui se résout, rend ce parent physique suivi du reste du nom ; `null` si le reste contient `..` ou `.` (un `..` après un élément absent n'a pas de sens physique), si un élément existant ne se résout pas (lien pendant, boucle, droits, ENOTDIR).
- Jamais de chemin émis tel quel : l'appelant (79-13) ramène le résultat à la racine du lab (amendements A22, A33) ou rend « un fichier hors du lab » sur `null`. Le chemin absolu ne sort jamais de la fonction vers une donnée publique.
- Stabilité : nom et signature sont figés par ce plan ; G17 de test-cockpit-git-config-depot.sh la protège ; le SUMMARY de ce plan répète cette section. Consommateurs prévus : 79-13 (cibles du radar, A23) et 79-16 (gardes de chemin de 79-06 et de serve.mjs, A37).
