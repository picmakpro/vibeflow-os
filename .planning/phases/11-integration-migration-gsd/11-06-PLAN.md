### 1. Dry-run 3 scopes + idempotence (isolé)

Pour chacun des 3 scopes, dans un `HOME=$(mktemp -d)` dédié (jamais le `$HOME` réel) :
```bash
for SCOPE in user project local; do
  SANDBOX="$(mktemp -d)"
  HOME="$SANDBOX" VF_SCOPE="$SCOPE" VF_ENSURE_DRY_RUN=1 VF_ENSURE_FORCE=1 \
    bash plugin/dev-orchestrator/scripts/ensure-deps.sh
  echo "scope=$SCOPE exit=$?"
  # Idempotence : 2e run, doit être un no-op strictement identique en sortie (hors horodatage éventuel).
  HOME="$SANDBOX" VF_SCOPE="$SCOPE" VF_ENSURE_DRY_RUN=1 \
    bash plugin/dev-orchestrator/scripts/ensure-deps.sh
  echo "scope=$SCOPE (2e run) exit=$?"
done
```
Vérifier pour chaque scope : exit 0 aux deux runs, la commande npx loguée en dry-run porte bien
`@opengsd/gsd-core@latest --claude` avec le bon flag (`--global` pour `user`, `--local` pour
`project`/`local`) — confirme que 11-01 n'a rien cassé côté dérivation de scope.

**Preuve « vrai `~/.claude` jamais touché »** : avant/après CETTE tâche complète, comparer un
snapshot (`find "$HOME/.claude" -newer <marker créé juste avant> 2>/dev/null`, où `$HOME` ici est

## Risques / points d'attention

- **La recette de vérification de `PROJECT.md` ci-dessus contient volontairement une
  auto-correction en cours de rédaction** — c'est le piège réel : un grep naïf sur tout le fichier
  après le renommage de la ligne 61 sortirait 0 occurrence de `get-shit-done-cc`, ce qui casserait
  silencieusement si quelqu'un « corrige » aussi la ligne 43 par excès de zèle. La bonne recette
  est `grep -n` (avec numéro de ligne) pour confirmer que la ligne 43 est intacte, pas juste que
  le compte global a changé.
- **Ne pas bumper la VERSION racine ni toucher `plugin.json`/`marketplace.json`** — c'est le
  garde-fou le plus important de ce plan (mandat explicite). Si l'exécuteur a un réflexe de
  clôturer une phase par une release complète (pattern vu en Phase 14), il doit s'arrêter au
  niveau module.
- **Dater les entrées CHANGELOG avec la date réelle d'exécution**, pas une date arbitraire — lire
  la date des entrées voisines les plus récentes pour vérifier le format exact utilisé par ce
  repo (`YYYY-MM-DD`).
- **Le compte de 39 suites est mesuré, pas supposé** — si la vague 11-04 a finalement ajouté plus
  d'un fichier de test, ou si un autre plan de cette phase a créé un fichier `test-*.sh`
  supplémentaire non prévu ici, recompter avec la commande exacte du gate
  (`scripts/check-version-sync.sh` point 9) avant d'écrire le chiffre en dur dans les README.
- **`test-merge-hooks.sh` et `test-gsd-cohabitation.sh` sont deux fichiers distincts** dans
  `plugin/_internal/tests/` — les deux comptent dans le total (le pattern `test-*.sh` les capture
  tous les deux), ne pas se limiter à vérifier un seul des deux en pensant qu'ils font double
  emploi.
