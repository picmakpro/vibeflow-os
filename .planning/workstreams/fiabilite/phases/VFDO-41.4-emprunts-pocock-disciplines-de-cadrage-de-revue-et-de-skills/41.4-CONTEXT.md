<decisions>
## Implementation Decisions

### Skills et défaillance observée (POCK-07, POCK-08)
- **P414-D-01 (classe d'invocation)** : chaque SKILL.md livré (26, `find` = `git ls-files`) déclare
  une classe vérifiée par machine, user-invoked ou model-invoked. `disable-model-invocation: true`
  n'est posé **que** sur les skills à effet de bord lourd qu'aucun agent, aucune commande et aucun
  préchargement n'appelle. `vf-dev`, `vf-auto`, `vf-design` restent model-invoked (Core Value :
  « aide-moi à dev » doit déclencher par langage naturel ; le head lance vf-auto et vf-design). La
  règle « un user-invoked n'en appelle jamais un autre » est vérifiée sur les arêtes d'appel. —
  **Reversibility:** reversible.
- **P414-D-02 (commandes)** : un skill appelé par une commande `plugin/commands/*.md`, par un agent
  (outil Skill ou routage) ou par préchargement (`skills:` d'un agent) ne peut pas passer
  user-invoked — le gate le refuse. **Rien n'est supprimé.**
- **P414-D-03 (gate et Codex)** : le contrôle étend `plugin/conductor/scripts/check-skills.sh` (le
  manifeste `check-agents-manifest.json` connaît déjà `disable-model-invocation`) ; check-skills.sh
  reçoit **sa propre étape** dans le job CI `gates` (il n'en a aucune aujourd'hui, il ne tourne que
  via sa suite). Équivalent Codex : `agents/openai.yaml` (`policy.allow_implicit_invocation: false`)
  posé sur les skills **nichés** (Type 2, `vf_place_tree` les transporte déjà) qui sont
  user-invoked ; les modules Type 1 (copie du SKILL.md seul, collision avec `plugin/<mod>/agents/`)
  sont **consignés comme dette**, pas traités. QUAL-01 : trois issues + mutation rouge.
- **P414-D-04 (défaillance observée)** : le trailer `Ajout-Retrait:` existant reçoit un segment
  obligatoire `défaillance : <session, geste ou commit daté>` ; `check-ajout-retrait.sh` surveille
  en plus les `SKILL.md` ajoutés (il les ignore aujourd'hui). Le gate **reste consultatif** en CI
  (warning, ADR-074 amendé) — pas de `--strict`. QUAL-01 s'applique.

### Revue à deux axes (POCK-04)
- **P414-D-05 (pilotage)** : le bloc typé de `vf-reviewer` porte `axes.standards` et `axes.spec`,
  chacun avec son `statut` et ses `findings`. Le nœud de revue ne passe que si les **deux** sont
  `passed` — une conjonction, jamais un classement. Les findings restent séparés par axe jusque
  dans le mandat de correction ciblée.
- **P414-D-06 (dispatch)** : `vf-reviewer` fait lui-même deux dispatches parallèles de
  `gsd-code-reviewer` : Standards (conventions du dépôt, smells, sécurité — le périmètre actuel) et
  Spec (jugé contre le PLAN de l'étape : manquant, non demandé, implémenté faux, avec la ligne de
  plan citée). Aucun agent neuf.
- **P414-D-07 (preuve)** : une sonde réelle — `vf-reviewer` dispatché sur un diff fabriqué propre
  mais qui omet une tâche du plan, sortie consignée en preuve E6 — plus un test statique du contrat
  (champs `axes.standards` / `axes.spec` présents dans la définition de l'agent et dans
  `mission-contracts.md`).

### Cadrage, glossaire, frontière, rétro, PR (POCK-01, 02, 03, 05, 06)
- **P414-D-08 (glossaire)** : le glossaire de domaine du lab est la section `## Vocabulaire` de
  `docs/_transverse/REFERENCE.md`, déjà posée par `scaffold-docs.sh` — **aucun fichier neuf** dans
  le gabarit. Le cadrage la met à jour (termes flous challengés, mots surchargés résolus) ;
  `docs-flow.md` l'adosse à la famille **savoir**. **Ce dépôt est scaffoldé d'abord** (« appliquer
  ici d'abord », précédent 41.3) : `docs/_transverse/` n'existe pas ici aujourd'hui.
- **P414-D-09 (frontière de phase)** : à la sortie d'un geste ou d'une mission, le head applique
  l'arbre continuer → clear → handoff → sous-agent → compact (en dernier, avec instruction) ; la
  question « qu'est-ce qui, dans l'environnement, aurait rendu la mission suivante moins chère ? »
  est **une ligne obligatoire de son contrat de sortie** (`head-governance.md` §3), captée au
  BACKLOG seulement si elle est actionnable. Aucun artefact neuf.
- **P414-D-10 (grille de rétro)** : doctrine dans `plugin/consolidator/references/promotion.md` ;
  `detect-promotions.sh` émet un champ `nature: mecanique|jugement` par candidate — une candidate
  mécanique propose un **check** (lint, hook, job CI) au lieu d'un brouillon de règle ; un dépôt
  sans garde-fou et une instruction sans effet (no-op) sont des findings du rapport. L'Iron Law de
  promotion (validation humaine) reste intacte.
- **P414-D-11 (merge-danger call)** : section obligatoire du corps de PR dans
  `mission-contracts.md` §Isolation de branche (« porte à sens unique / double sens ; rayon
  d'explosion »), vérifiée à la sortie par le contrôle E3 de `check-mission-exit.sh`. QUAL-01
  s'applique (E3 est un gate modifié).

### Décisions du manager (périmètre d'implémentation)
- **P414-D-12 (POCK-01, emplacement)** : la discipline de frontière de questions (un tour = toute
  la frontière, numérotée ; une recommandation par question ; un fait ne se demande jamais à
  l'humain, un sous-agent le cherche ; rendu AskUserQuestion groupé par zone, jamais en texte ; fin
  de cadrage = frontière vide) s'écrit dans **une** référence — `mission-flow.md` §Pattern F pour
  le manager, un renvoi depuis `head-governance.md` pour le head — et **pas** dans
  `vf-dev-manager.md` (250 lignes, alerte à 251). Accord de Samuel sur ce point dans le même relais
  du 2026-10-06. Elle **resserre** la prose existante : `vf-dev-manager.md:23` (« contexte + options
  + recommandation »), `intent-routing.md:45` et `:119-124` (« une question courte »).
- **P414-D-13 (SOBR-05)** : chaque commit qui ajoute de la doctrine nomme ce qu'il remplace ou
  resserre ; chaque gate modifié porte `Gate-Touche:` ; tout ajout surveillé par
  `check-ajout-retrait` porte `Ajout-Retrait:` — **avec le segment de défaillance de P414-D-04**,
  appliqué à la phase elle-même (la défaillance de référence : étude §5, et pour POCK-07 les arêtes
  vf-dev → vf-auto / vf-design mesurées le 2026-10-06).
- **P414-D-14 (versions)** : bump `VERSION` + `CHANGELOG.md` de chaque module touché
  (dev-orchestrator v2.26.0, conductor v1.46.0, consolidator v1.10.0, plus tout module dont un
  SKILL.md change de frontmatter) ; **jamais** la `VERSION` racine (release = geste humain).
- **P414-D-15 (textes périmés croisés)** : `check-skills.sh:6` (« 25 SKILL.md », il y en a 26) et
  le commentaire `ci.yml:1595` (« cinq mutants », il y en a neuf) se corrigent dans le lot qui
  touche ces fichiers — une incohérence que la phase touche se ferme, elle ne s'élargit pas au-delà.
- **P414-D-16 (tension de routage)** : `intent-routing.md:76` route « crée une PR / ship » vers
  `gsd-ship`, alors que l'ouverture de PR est un geste VibeFlow (`GSD-PIPELINE.md:122`). Le lot
  POCK-06 **consigne** la tension (BACKLOG) sans changer le routage — changer une route est hors
  périmètre de la phase.

### Established Patterns
- Gates in-repo : trois issues + mutation rouge (QUAL-01), trailer `Gate-Touche:` sur tout commit qui touche un gate, sa suite ou ci.yml.
- Doctrine : une seule voix (ADR-030) — l'agent renvoie à la référence, ne la recopie pas.
- Budgets : agents ≤ 300 lignes (alerte 251), ratchet d'instructions (baseline) — toute hausse d'instructions d'agent exige une citation d'arbitrage dans le commit (G-1).

### Integration Points
- Job CI `gates` (nouvelle étape check-skills.sh, E3 de check-mission-exit, check-ajout-retrait).
- 26 SKILL.md sur 10+ modules (frontmatter de classe) ; installeur Type 2 pour `agents/openai.yaml`.
