## Conventions communes à ce plan

- Chemins relatifs à la racine du dépôt ; le clone amont vit dans un dossier jetable `mktemp -d` hors de tout dépôt, jamais
  dans l'arbre ; aucun chemin de machine écrit dans un fichier suivi.
- PIÈGE `git apply` : lancé dans un sous-dossier d'un dépôt, il interprète les chemins du patch depuis la racine du dépôt et
  ignore en silence ceux qui sortent du dossier courant. Toute application ou inversion de patch se fait donc dans un dossier
  jetable hors dépôt, `GIT_CEILING_DIRECTORIES` réglé sur son parent, avec `--verbose` (chaque patch doit dire « Applied
  patch … cleanly »), puis copie vers la destination.
- PIÈGE U+2028/U+2029 (CONVENTIONS des spikes) : l'outil d'écriture convertit les échappements en caractères réels ; dans
  le source, les écrire sous forme échappée et vérifier par décompte (aucun caractère réel dans les `.mjs` écrits).
- Notre code ≤ 300 lignes par fichier (P67-D-07) ; suites au harnais de `test-dag.sh` (anti-vert-à-vide), fixtures
  reconstruites dans `mktemp -d`, isolation git (`GIT_CONFIG_NOSYSTEM=1`, `GIT_CONFIG_GLOBAL` vers un fichier vide,
  identité posée par `-c`), aucun `timeout`/`gtimeout`, attente bornée par boucle de `sleep 0.1` ; serveurs de test lancés
  avec `--no-open --port <p>` et port réel lu dans `<sortie>/.cache/server.json`, arrêtés par `kill` puis `wait`.
- Notre code appelle l'API amont par ses noms amont (globales, en-tête de jeton, marqueur de données), renommés ensemble à
  l'assemblage ; tout le reste de notre code est déjà nommé VibeFlow.
- rtk : vérifications par `rtk proxy <commande>` sur un poste où rtk réécrit les commandes ; lire du JSON servi par `fetch`
  Node, jamais `curl` à travers rtk.
- Compteur « N suites » des README racine tenu par ce plan (tâche 3) : valeur = `find plugin scripts -type f -path '*/tests/test-*.sh' | grep -c .` mesurée après les suites de ce plan.
- Commits en français, identifiants `P67-D-NN`, aucune VERSION racine ni release.
