# Plan 14-04 — Rescope du SKILL : description et branchement

## But

C'est le plan qui règle la **moitié cachée** du problème. Tant que la description revendique « fais-moi
une feuille de route » et « où en est-on ? », `vf-planning` concurrence le moteur de dev **au matching
sémantique** — et quand il perd l'arbitrage, il n'est jamais invoqué, donc aucune redirection interne ne
peut rattraper le coup. On désarme donc la description *et* on câble le branchement.

Complète le critère de succès 2 du ROADMAP. Vague 2 : dépend de 14-01 (le script appelé à l'étape 0) et
de 14-02 (la référence citée).

## Exigences couvertes

ALTI-02.

## Tâches

Le **contenu exact** (description YAML, section « Étape 0 », séquence B, garde-fous, anti-patterns) est
dans la **Task 4** du plan détaillé : `docs/superpowers/plans/2026-07-25-rescope-vf-planning-gsd.md`.

1. Remplacer intégralement le bloc `description:` du frontmatter par la version rescopée.
2. Insérer la section **« Étape 0 — Qui tient le planning de ce lab ? »** juste avant
   `## Séquence — Mise en place`.
3. Renommer les deux titres de séquence existants en **Séquence A** (socle universel, lab non-dev) et
   **Séquence A (suite) — Maintenance**, puis ajouter la **Séquence B** (couche lab au-dessus de GSD).
4. Compléter les sections **Garde-fous** (+1), **Anti-patterns** (+3) et **Références** (+2).

  `sed -n '/^description:/,/^---$/p' plugin/planning-core/SKILL.md | grep -ci "feuille de route\|où en est-on"` → **0**.

  `for v in vf-init vf-progress vf-plan vf-map; do sed -n '/^description:/,/^---$/p' plugin/planning-core/SKILL.md | grep -q "$v" || echo "MANQUE $v"; done` → aucune sortie.
- Les 5 ancrages structurels existent :
  `grep -c "Étape 0\|Séquence A\|Séquence B\|gsd-handoff\|detect-gsd-engine" plugin/planning-core/SKILL.md` ≥ 5.
- La plomberie ne fuite pas :
  `grep -c "gsd-new-project\|gsd-progress\|gsd-plan-phase\|get-shit-done" plugin/planning-core/SKILL.md` → **0**
  (seul `detect-gsd-engine.sh`, script du module, porte « gsd » dans son nom — c'est attendu).

  `grep -c "aucun artefact de projet\|Ne générer aucun artefact" plugin/planning-core/SKILL.md` ≥ 1.

## Risques / points d'attention

- **Ne pas casser la séquence A.** Les 4 bundles non-dev (`content`, `business-pilot`, `growth`,
  `kpi-analyst`) en dépendent et la citent (`BUNDLE.md` : « déléguer à `vf-planning` »). Le fond de la
  séquence historique ne change pas — seul son **titre** change, et le branchement qui y mène.
- **La description est le livrable critique**, pas le corps. C'est elle qui décide si le skill se déclenche.
  Une description encore ambiguë rend les 5 autres plans inopérants dans le cas courant.
- **Densité** : le détail de la doctrine appartient à `gsd-handoff.md` (14-02), pas au SKILL. Si l'étape 0
  dépasse ~40 lignes, c'est le signe qu'on recopie la référence au lieu de la charger.
- **Ne pas ajouter de logique de migration ici** : l'étape 0 se contente de router vers le protocole de
  `gsd-handoff.md` sur exit 2.
