# Phase 40.1 — Plan 02 : base de branche dérivée, bump dérivé, invariants de phase (Summary)

Trois instruments robustes au hotfix v2.63.1 fusionné dans `main` avant l'exécution : aucun sha,
aucun numéro de version et aucun sujet de commit ne conditionne une preuve de la Phase 40.1.

## Performance

- **Duration:** ~55 min
- **Tasks:** 3/3 (Task 0 précondition, Task 1 base+bump, Task 2 invariants)
- **Commits:** 2 (`4cc341b`, `dcbb1b1`)

## Accomplishments

- **Task 0 (précondition, lecture seule)** : la base résolue par la règle W-C sans dépendre de
  `tools/` (qui n'existe pas encore en vague 1) contient le hotfix v2.63.1 — `VERSION` ≥ v2.63.1,
  entrée CHANGELOG `dev-orchestrator` v2.63.1 présente, base = pointe de `origin/main`/`main`
  (les deux égales à `61d80bf`). Vert, exécution poursuivie.
- **`tools/phase-base.sh`** : résout la ref main (`--main-ref` prioritaire, sinon la plus avancée
  entre `origin/main` et `main` via `git merge-base --is-ancestor`, rc 2 explicite sur divergence)
  et imprime `git merge-base HEAD <ref>`. Aucun sha littéral dans le script.
- **`tools/check-module-bump.sh`** : dérive la cible de bump (patch/minor) depuis la VERSION qui
  précède le dernier commit **propre à la branche** touchant `plugin/<module>/VERSION`
  (`git rev-list --no-merges HEAD --not <base> -- <chemin>`), puis vérifie la triade VERSION ↔
  module.json ↔ CHANGELOG (`Phase 40.1`) ↔ README, et que ce même commit touche aussi module.json
  et CHANGELOG.md. Aucun filtre par sujet de commit.
- **`tools/check-phase-invariants.sh`** : (M) aucune résolution de merge propre ne touche un
  chemin gardé ; (I1) la baseline d'instructions est touchée par au moins un commit propre sans
  que ses lignes de données changent ; (I2) chaque ligne d'agent modifiée par un commit propre est
  un remplacement de valeur pur (fonction awk `swap`, frontière de nombre) — nombre d'ajoutées =
  nombre de retirées par fichier, ≥ `--min-agents` fichiers distincts vérifiés ; (I3) le gate
  budget ne monte jamais (toute hausse rouge), et les fichiers de l'ensemble I2 collent exactement
  à leur baseline (une marge de hotfix reste tolérée hors de cet ensemble) ; (I4) aucun commit
  propre ne touche une source de version racine.
- Deux suites de fixtures jetables : `test-check-module-bump.sh` (15 cas B1-B15) et
  `test-check-phase-invariants.sh` (13 cas V1-V13), toutes deux vertes **sous `set -e`** (le mode
  d'invocation exact du `<verify>` du plan) — ce qui a nécessité de corriger `rc_of()`/`pb_case()`
  et leurs appelants pour capturer un code de retour non nul sans jamais interrompre le script.
- Sur l'arbre d'avant-phase (aucun `tools/` avant ce plan) : `check-module-bump.sh conductor minor`
  rend 1 (aucun bump propre) et `check-phase-invariants.sh` rend 1 avec `I1=ko I2=ko` (diff vide
  jamais vert) — preuves rouges exigées par le plan, jouées et vérifiées.
