Écrire le script bash, exécutable (`chmod +x`), dans le style de `scripts/check-release-tag.sh` :
en-tête `# ` auto-documenté servi par `--help` (`grep '^# ' "$0" | sed 's/^# //'`), `set -euo pipefail`,
messages préfixés `[traffic-snapshot]`, codes de sortie documentés (0 conforme · 1 échec d'appel ou
de fusion · 2 usage/prérequis manquant).

Interface :
`traffic-snapshot.sh [--repo OWNER/NAME] [--out CHEMIN] [--dry-run] [--help]`
— `--repo` par défaut `picmakpro/vibeflow-os` ; `--out` par défaut `traffic.json` ; `--dry-run`
émet le JSON fusionné sur stdout sans écrire le fichier.

Prérequis vérifiés au démarrage, chacun avec son propre message et exit 2 : `gh` absent, `jq` absent.

**Séparation des jetons (point dur du cadrage).** L'API traffic exige un accès admin/push que le
`GITHUB_TOKEN` d'Actions n'a pas ; le comptage des jobs, lui, s'en contente. Isoler les appels
derrière quatre fonctions minces, seul endroit du script qui parle au réseau :
`api_traffic_clones`, `api_traffic_views`, `api_runs_page`, `api_run_jobs`. Les deux premières
invoquent `gh` avec `GH_TOKEN="$TRAFFIC_PAT"` **uniquement si** la variable est non vide, sinon
elles retombent sur l'authentification ambiante de `gh` (cas du poste de Samuel). Les deux
dernières utilisent l'authentification ambiante telle quelle. Ne jamais imprimer la valeur d'un
jeton, ni activer `set -x` dans le script.

**Diagnostic 403.** Si un appel traffic échoue, capturer le corps de la réponse et, lorsqu'il porte
un code 403 (ou que `gh` sort non-zéro sur ces deux endpoints), émettre sur stderr un message qui
nomme la cause — l'endpoint traffic réclame un droit `Administration: read`, que le jeton employé
n'a pas — puis renvoyer le chemin de correction (créer un PAT fine-grained sur le seul repo et le
poser en secret `TRAFFIC_PAT`), et sortir en 1. Jamais de repli sur un objet vide.

**Fenêtre de calcul.** La borne basse est le plus ancien `timestamp` présent dans l'union des
payloads clones + vues, tronqué à 10 caractères. Aucun appel à `date -d` ni `date -v` (voir
contrainte 5). Cette borne alimente le filtre `created=>=<DATE>` de l'endpoint `runs`, encodé
`created=%3E%3D<DATE>`.

**Comptage CI.** Paginer `actions/runs` avec `--paginate` en streamant `.workflow_runs[] | [.id, (.created_at[0:10])]`,
puis, pour chaque run, lire `total_count` de `actions/runs/<ID>/jobs?filter=all&per_page=100` et
accumuler par date. Environ 100 appels sur une fenêtre de 14 jours (~1 min) : émettre une trace de
progression sur stderr pour que l'exécution ne paraisse pas figée, jamais sur stdout (stdout porte
le JSON en `--dry-run`). Approximation à documenter en commentaire : les jobs sont attribués à la
date de création de leur run, donc un run créé à 23h58 dont les jobs tournent après minuit est
compté la veille.

**Forme du fichier.** Objet dont les clés de premier niveau sont des dates `YYYY-MM-DD` — pas de clé
de métadonnées, la forme doit rester directement exploitable par `jq`. Chaque valeur :
`{clones, clones_uniques, views, views_uniques, ci_jobs, clones_adjusted}`. L'ensemble des dates est
l'**union** de celles vues côté clones et côté vues ; une métrique absente d'un des deux payloads
vaut `0`. `clones_adjusted` = `max(0, clones - ci_jobs)` — la borne à zéro n'est pas cosmétique :
les jobs d'un run peuvent déborder sur le lendemain et rendre la soustraction négative.

**Fusion idempotente.** Lire le `--out` existant (objet `{}` s'il est absent, vide ou illisible),
puis fusionner avec `jq -S 'ancien * frais'` : les dates fraîches écrasent, les dates absentes du
nouveau payload sont conservées telles quelles, aucune n'est supprimée. `jq -S` trie les clés, et
l'ordre alphabétique des dates ISO est l'ordre chronologique. Écriture atomique : fichier temporaire
puis `mv`, pour qu'un échec en cours de route ne laisse pas un `traffic.json` tronqué.

**Couture de test (tâche 2).** Si `VF_TRAFFIC_FIXTURES` est défini et non vide, les quatre fonctions
d'appel lisent les payloads sur disque au lieu du réseau — `$VF_TRAFFIC_FIXTURES/clones.json`,
`views.json`, `runs.json`, `jobs/<ID>.json` — et rendent le JSON **verbatim**. La couture s'arrête
là : parsing, agrégation par jour, calcul de l'ajustement, fusion et écriture restent le chemin de
production, sans variante. Ce repo a déjà été mordu trois fois par un test qui n'exerçait pas le
code réellement émis (Phases 13, 17, 19) — la couture n'injecte que des réponses d'API, jamais un
résultat.
