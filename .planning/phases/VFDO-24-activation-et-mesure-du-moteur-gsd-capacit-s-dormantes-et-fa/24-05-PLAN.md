<objective>
Rendre bruyante la défaillance que le moteur traite en silence : une session qui ouvre sur un
`.planning/` partitionné sans workstream résolu.

Purpose: le pointeur de workstream ne vit pas dans le dépôt dès qu'une clé de session résout — il
vit dans `os.tmpdir()/gsd-workstream-sessions/<condensat du chemin absolu du .planning>/<clé>`.
Mesuré le 2026-08-04 dans ce runtime : `CLAUDE_CODE_SSE_PORT` est présent, donc c'est bien
l'adaptateur `tmpdir` qui est retenu sous Claude Code. Ce pointeur est effacé au redémarrage, indexé
sur le chemin absolu, **distinct par worktree et jamais hérité** : il ne se compose pas avec
ADR-064. Pire, `getActiveWorkstream` **auto-nettoie en silence** — nom invalide ou dossier
inexistant, il efface le pointeur et rend « aucun workstream », sans un mot.

Output: un gate qui refuse ce silence, prescrit le remède le moins coûteux (`GSD_WORKSTREAM`, canal
de premier rang), et une suite dédiée qui prouve sa discriminance par mutation.
</objective>

Rôle, à écrire en tête : constater si le workstream actif d'un dépôt partitionné est résolu par un
canal **composable avec ADR-064**, et échouer bruyamment sinon — parce que le canal par défaut du
moteur sous ce runtime ne l'est pas.

États mutuellement exclusifs, évalués dans cet ordre, le premier qui matche gagne :

0. Le dossier `<root>/.planning/workstreams/` n'existe pas → dépôt non partitionné, rien à vérifier
   → **exit 3** (silence, sortie vide sur stdout).
1. Un workstream est résolu par `GSD_WORKSTREAM` (non vide, nom valide) **et**
   `<root>/.planning/workstreams/<nom>/` existe → **exit 0**, message de conformité nommant le
   workstream et le canal (`env`).
2. Aucun `GSD_WORKSTREAM`, mais le pointeur partagé in-repo `<root>/.planning/active-workstream` est
   lisible, son contenu est un nom valide, et le dossier correspondant existe → **exit 0**, canal
   `store-partagé`.
3. Un nom est résolu par l'un des deux canaux mais `<root>/.planning/workstreams/<nom>/` **n'existe
   pas** → **exit 1**. C'est exactement l'auto-nettoyage silencieux du moteur rendu audible : dire
   que le moteur, lui, effacerait le pointeur et rendrait « aucun workstream » sans un mot.
4. Dépôt partitionné, aucun des deux canaux composables ne résout → **exit 1**, avec le message qui
   porte le fait et le remède :
   – le fait : le pointeur de session vit dans
     `os.tmpdir()/gsd-workstream-sessions/<condensat sur 16 du chemin absolu réel du .planning>/<clé de session>`,
     il est effacé au redémarrage, indexé sur le chemin absolu, donc **distinct par worktree et
     jamais hérité** — non composable avec ADR-064 ;
   – le remède, dans cet ordre : `export GSD_WORKSTREAM=<nom>` dans le worktree (canal de premier
     rang, il court-circuite le pointeur de session), ou `gsd-tools workstream set <nom>` si le
     runtime n'expose aucune clé de session.

Non vérifiable → **exit 2** : hors dépôt git, `<root>/.planning/` illisible, pointeur partagé
présent mais illisible, ou nom lu hors de la classe de caractères du moteur. Jamais exit 0 dans ces
cas. Usage → **exit 64**.

Options : `--path <dir>` (défaut `.`), `--hook` (change **uniquement** le format d'affichage, jamais
les codes de sortie — parité avec les autres gates de ce dépôt), `-h/--help`. Env de surcharge pour
la testabilité : un chemin de `.planning` surchargeable (patron `VF_*_PLANNING_DIR`) et
`GSD_WORKSTREAM`. Chaque code de sortie est énuméré dans la docstring, aucun implicite.

Le script est en **lecture seule** : il ne crée, ne modifie et n'efface aucun fichier — surtout pas
le pointeur, dont l'effacement est précisément le comportement qu'il dénonce.

Marquer le fichier exécutable.
