## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Suites bash maison (patron `ok`/`ko` à trois champs assertion/attendu/obtenu), aucune dépendance tierce |
| **Config file** | none — chaque suite est un script autonome `*/tests/test-*.sh` ; outils de preuve de phase sous `tools/` |
| **Quick run command** | `bash --noprofile --norc -e plugin/conductor/scripts/tests/test-check-instruction-budget.sh` (~2 s) et `bash --noprofile --norc -e <phase>/tools/check-no-live-250.sh .` (~1 s) |
| **Full suite command** | `<phase>/tools/replay-ci-jobs.sh --job gates` puis `--job tests` : étapes extraites de `.github/workflows/ci.yml`, lancées en `bash --noprofile --norc -e` (aucun `shell:` déclaré, donc pas de pipefail) |
| **Estimated runtime** | quick ≤ 10 s ; preuves de tâche ≤ 3 min (suite dev-orchestrator mesurée à 38 s, jouée deux fois par preuve) ; rejeu complet plusieurs minutes |

`<phase>` = `.planning/phases/VFDO-40.1-r-vision-adr-029-et-du-gate-du-budget-d-instructions`.
Sur ce poste, toute commande est lancée via `bash --noprofile --norc -e …` : cette forme n'est pas
réécrite par le hook rtk (mesuré : `wc -l` d'un flux vide y rend 0) ; les outils comptent en awk,
jamais `wc -l` ni `grep` proxifiés.

---

## Sampling Rate

- **After every task commit:** quick run (suite du gate + recensement filtré sur la famille du plan) ; `check-instruction-budget.sh` rend 0 sur le dépôt armé
- **After every plan wave:** `replay-ci-jobs.sh --job gates` ; en vague 4, `--job tests` en plus
- **Before `/gsd-verify-work`:** plan 40.1-14 complet (recensement nul, deux contrôles négatifs, rejeu tests+gates, invariants)
- **Max feedback latency:** quick ≤ 10 s ; preuve de tâche ≤ 3 min

## Couplages hors fichiers (déclarés à la révision 1)

- **Suites conductor ↔ auditeur et audit-architecture** : `test-check-description-fidelity.sh` copie
  les SKILL.md modifiés par 40.1-05 et 40.1-12. 40.1-04, qui rejoue toutes les suites conductor, est
  donc SÉRIALISÉ après eux (vague 3). En vague 2, 40.1-05 et 40.1-12 jouent eux-mêmes cette suite
  sur leur propre état.
- **`check-version-sync.sh` ↔ toutes les triades** : il lit les triades de tous les modules. Chaque
  bump de la phase écrit VERSION, `module.json`, l'en-tête README et le CHANGELOG dans UN seul commit,
  donc aucun état intermédiaire n'est visible d'un plan parallèle ; aucune sérialisation requise.
- **Suite dev-orchestrator ↔ hotfix v2.63.1** : la suite lit `AGENT.md` et `vf-coder.md`, que le
  hotfix modifie. 40.1-07 et 40.1-14 exigent une base contenant le hotfix (précondition nommée), et
  aucun plan n'écrit dans les fichiers du hotfix.
- **Manuel (40.1-13) ↔ README conductor (40.1-04)** : couplage supprimé. Le manuel s'appuie sur des
  faits mesurés sur les tags (`git tag --contains a7f414a`), plus sur le README.
- **Bumps ↔ numéros de version** : aucun numéro figé ; toute cible est dérivée à l'exécution par
  `tools/check-module-bump.sh`.
