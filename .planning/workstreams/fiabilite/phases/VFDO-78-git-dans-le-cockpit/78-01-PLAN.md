- `git --no-ext-diff log -1` rend 129 : les options `--no-ext-diff --no-textconv` se placent APRÈS la sous-commande, jamais en
  préfixe global (le libellé « préfixe GIT_LECTURE » de P78-D-22 se lit donc « options de lecture insérées »).

  `filter.f.required=true` ; sans la parade, `status` sur un fichier stat-dirty lance `filter.f.process`.
- `GIT_CONFIG_COUNT=1 GIT_CONFIG_KEY_0=… GIT_CONFIG_VALUE_0=…` est lu par git 2.50 (portée « ligne de commande »).
- `GIT_DIR=<autre> git -C <dépôt> log -1` lit `<autre>` : `-C` ne protège pas.

## Artifacts this phase produces

- `plugin/cockpit/scripts/vf-cockpit-paths.mjs` — symboles neufs :
  - `GIT_HERITE` (`/^GIT_/i`) : toute clé héritée qui y répond est retirée de l'environnement d'un enfant git ;
  - `envGit(lab, { env = process.env, config = [] } = {})` : `envEnfant(lab, env)` sans clé `GIT_*`, plus `GIT_OPTIONAL_LOCKS=0`,
    `GIT_CONFIG_COUNT`/`GIT_CONFIG_KEY_<i>`/`GIT_CONFIG_VALUE_<i>` portant `core.fsmonitor=false` puis chaque paire de `config`, plus
    le marqueur `VF_COCKPIT_GIT_DURCI=1` (lu par la garde du moteur, plan 78-07) ;
  - `filtresDeclares(dir, lab = dir)` : noms des pilotes de `git config --name-only --get-regexp '^filter\.'` (sous-section entre le
    premier `filter.` et la dernière `.clé`), au plus 64, appel lancé avec `envGit` sans filtre ;
  - `configFiltres(noms)` : pour chaque nom, `filter.<x>.clean=`, `filter.<x>.smudge=`, `filter.<x>.process=`, `filter.<x>.required=false` ;
  - `OPTIONS_LECTURE` (`{ log, show: ['--no-ext-diff', '--no-textconv', '--no-show-signature'], 'diff-tree', diff: ['--no-ext-diff', '--no-textconv'] }` :
    l'environnement retire `GIT_CONFIG_GLOBAL`, la config globale de l'utilisateur s'applique donc ; un `log.showSignature=true` y
    ajouterait la sortie gpg et désalignerait les parseurs, d'où `--no-show-signature`, que `diff-tree` refuse) et `SOUS_COMMANDES_FILTRANTES` (`status`, `diff`, `ls-files`, `stash`) ;
  - `argsGit(args)` : `{ argv, sous, dir }` — repère la sous-commande après les options globales (`--no-optional-locks`, `-c <v>`,
    `-C <dir>`), insère les options de `OPTIONS_LECTURE` de la sous-commande juste après elle ;
  - `shBorne(cmd, args, cwd, lab)` : signature et retour inchangés ; pour `git`, argv de `argsGit`, `env: envGit(lab, { config })`
    avec `config = configFiltres(filtresDeclares(dir || cwd, lab))` si `sous` est filtrante, `maxBuffer` explicite (1 Mio) ;
  - `lancerGit(dir, args, { lab = dir, maxBuffer = 4 << 20, binaire = 'git' } = {})` : `{ ok, sortie, code, tronque, absent }`,
    même exécuteur interne et même échéance que `shBorne`, `GIT_SUR` et `-C dir` posés par la fonction ; `ok` seulement sur code 0
    sans ENOBUFS ; `absent` sur ENOENT (`binaire` sert aux tests du cas « git introuvable », jamais lu d'une variable d'environnement).
