<objective>
**Addendum approuvé le 2026-08-15, hors périmètre du cadrage d'origine de la Phase 30.**

D-01 (`30-CONTEXT.md`) fait écrire au moteur d'install un **chemin absolu d'interpréteur** dans le
champ `command` des entrées de hook en forme exec (jeton résolu à l'install, routé vers le fichier
de réglages local). La décision est **one-way** et assumée — mais elle crée un mode de panne
**silencieux** que rien ne surveille aujourd'hui : le jour où ce chemin devient périmé
(interpréteur mis à jour, Git Bash réinstallé ailleurs, `brew upgrade`, `settings.local.json`
recopié d'une machine à l'autre), le hook **cesse simplement de tourner**. Pas d'erreur, pas de
message : juste mort. Tout le substrat livré par cette phase deviendrait inerte sans que personne
ne le sache.

Ce plan livre le filet qui rend cette panne **constatable** : un cinquième signal `SessionStart`
advisory, `check-hook-paths.sh`, qui relit les réglages réellement posés, vérifie que chaque chemin
absolu d'entrée en forme exec existe et est exécutable, et le dit — une fois, brièvement, sur le
chemin où il y a quelque chose à dire ; **strictement rien** sinon.

**Le paradoxe d'amorçage, qui gouverne tout le reste :** ce filet ne peut pas être invoqué par le
chemin absolu figé à l'install, sinon il mourrait exactement dans le scénario qu'il doit détecter.
Son entrée de hook porte donc un `command` **littéral** `bash`, résolu à l'exécution — une
**dérogation à ADR-071 §Décision 2** (« jamais un nom nu »), qui ne prévoit **aucune clause
d'exception** : la dérogation est autorisée par l'**approbation humaine de cet addendum
(2026-08-15)**, pas par l'ADR elle-même, qui ne documente pas encore ce cas. Elle est
**machine-gardée par un test** pour qu'un futur relecteur ne la « corrige » pas en croyant réparer
une incohérence — et le fait qu'ADR-071 reste muette dessus est un **reliquat nommé**, consigné au
SUMMARY, jamais une ratification affirmée au présent.

**Ordonnancement — précondition d'ordre avec le plan 30-08 :** ce plan ajoute **une suite** au
dépôt (60 → 61). La tâche 2 du plan 30-08 remet les compteurs de suites des deux README racine à
l'heure, et ces deux fichiers sont **hors du périmètre de ce plan**. Ce plan doit donc s'exécuter
**AVANT** la tâche 2 de 30-08. S'il s'exécute après, le delta +1 devient un signalement explicite
au SUMMARY, jamais une édition de README faite ici.

Purpose: fermer l'angle mort de silence d'une décision one-way, sans lui retirer sa décision.
Output: un script, une suite, une 26e entrée de hook, un inventaire durable remis à l'heure.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| install (passé) → session (présent) | Un chemin absolu d'interpréteur est gravé à l'install et relu bien plus tard : le monde a pu changer entre les deux. C'est la frontière que ce plan instrumente. |
| fichiers de réglages → filet | Les réglages lus peuvent être mal formés, partiels, ou écrits par un tiers (gsd-core, un autre outil) : entrée non maîtrisée d'un script qui tourne à chaque démarrage. |
| filet → contexte de session | Tout stdout émis à code 0 sur `SessionStart` est injecté comme contexte : le canal de sortie est un budget de jetons, pas un journal. |
| filet → sa propre chaîne de dépendances | Le filet dépend d'un interpréteur de commandes, d'une lib partagée et d'un interpréteur Python : chacune de ces dépendances peut, elle aussi, devenir muette. |
