# Plan 12-04 — Réécriture des 15 descriptions existantes

## But

Mettre les verbes déjà livrés au même standard déclencheur que les neufs, et **fermer les
démarcations croisées** : un contre-exemple n'est efficace que si son pendant existe de l'autre
côté. Rend vrai le critère de succès 3 du ROADMAP.

## Exigences couvertes

VERB-03.

## Tâches

1. Réécrire la **description** (frontmatter uniquement) des 14 skills de `dev-orchestrator` :
   `vf-auto`, `vf-brainstorm`, `vf-debug`, `vf-decide`, `vf-dev`, `vf-execute`, `vf-init`, `vf-map`,
   `vf-plan`, `vf-progress`, `vf-quick`, `vf-review`, `vf-ship`, `vf-test`.
2. Réécrire la description de `plugin/design-orchestrator/skills/vf-design/SKILL.md` (déjà dense —
   la retoucher pour ajouter les contre-exemples, pas pour la réduire).
3. **Démarcations croisées obligatoires** (pendants des contre-exemples posés en 12-02/12-03) :

   | Fichier | Contre-exemple à ajouter |
   |---|---|
   | `vf-test` | ✘ pas pour écrire les tests manquants → `/vf-testgen` |
   | `vf-review` | ✘ pas pour les audits UAT / la dette d'étape → `/vf-gaps` |
   | `vf-map` | ✘ pas pour extraire les décisions / le graphe de connaissance → `/vf-learn` |
   | `vf-progress` | ✘ pas pour recharger le contexte d'une session passée → `/vf-resume` |
   | `vf-brainstorm` | ✘ idée floue → `/vf-explore` · ✘ code jetable → `/vf-spike` · ✘ figer le QUOI → `/vf-spec` |
   | `vf-debug` | ✘ pas pour un post-mortem de cycle raté → `/vf-forensics` |
   | `vf-plan` | ✘ pas pour éditer la feuille de route → `/vf-phase` · ✘ pas pour figer le QUOI → `/vf-spec` |
   | `vf-ship` | ✘ pas pour trier les issues / PR entrantes → `/vf-inbox` |
   | `vf-execute` | ✘ pas pour une expérimentation jetable → `/vf-spike` |
   | `vf-init` | ✘ pas pour ouvrir un nouveau jalon sur un projet existant → `/vf-milestone` |
   | `vf-design` | ✘ pas pour une maquette jetable → `/vf-sketch` |
   | `vf-quick`, `vf-auto`, `vf-decide`, `vf-dev` | gabarit appliqué ; contre-exemple vers le voisin le plus proche (`/vf-execute`, `/vf-progress`, `/vf-brainstorm`) |

4. **Ne pas** modifier le corps des skills au-delà des renvois de démarcation. Aucune évolution de
   comportement dans ce plan.

## Comment on vérifie (recette)

- Chaque `SKILL.md` touché contient au moins un `✘` dans sa description.
- Les 6 paires sont **bidirectionnelles** : pour chaque paire (A,B), A cite B **et** B cite A.
- `bash plugin/dev-orchestrator/scripts/tests/test-dev-orchestrator.sh` → T5 vert, T9/T10 non
  régressés (les renvois `mission-contracts` de `vf-auto` sont préservés).
- `git diff` sur les 15 fichiers : hors frontmatter, seuls des renvois de démarcation ajoutés.

## Risques / points d'attention

- **Régression T9/T10** : `vf-auto/SKILL.md` porte `SEUIL_EQUIPE`, `vf-dev-manager` et le renvoi
  `mission-contracts`. Une réécriture trop large les efface et casse deux tests. Ne toucher que la
  description.

  *repousser* au moins une intention voisine.
- **Couture avec 12-02/12-03** : ce plan écrit les *pendants* de contre-exemples dont les originaux
  sont dans des plans parallèles. Les noms de verbes cités doivent correspondre exactement — le
  contrôle machine de bidirectionnalité est en 12-06 (T12).
