# Plan 12-03 — `vf-sketch` dans `design-orchestrator`

## But

Donner une porte d'entrée au geste « maquette-moi ça » sans le faire fuiter dans le module dev.
Complète le critère de succès 2 du ROADMAP (18ᵉ verbe de la Phase 12).

## Exigences couvertes

VERB-02 (part `design-orchestrator`), VERB-03.

## Tâches

1. **`plugin/design-orchestrator/skills/vf-sketch/SKILL.md`** (nouveau) :
   - Description sur le gabarit : « maquette-moi ça », « une idée d'écran », « mockup jetable »,
     « montre-moi à quoi ça ressemblerait », « esquisse deux ou trois variantes ».
   - Contre-exemples : *✘ pas pour définir la direction artistique / refaire une interface réelle →
     `/vf-design`* · *✘ pas pour expérimenter du code fonctionnel jetable → `/vf-spike`*.
   - Portée d'invocation : par l'utilisateur ET par l'agent `vibeflow-design` en autonomie.
   - Corps : délégation à `gsd-sketch` (maquettes HTML jetables, mode frontière) + reframe VibeFlow
     (« sketch » → **maquette jetable**) + enchaînement typique (`vf-sketch` → `/vf-design` une fois
     la piste retenue).
2. **`plugin/design-orchestrator/AGENT.md`** : ajouter le verbe à la table de routage de
   `vibeflow-design` (une ligne), sans dépasser 250 L. Réaffirmer que `gsd-ui-phase` /
   `gsd-ui-review` restent routés en interne par `/vf-design` — pas de verbe dédié.

## Comment on vérifie (recette)

- `test -f plugin/design-orchestrator/skills/vf-sketch/SKILL.md` et `wc -l` ≤ 500.
- `grep -c 'vf-sketch' plugin/design-orchestrator/AGENT.md` ≥ 1 ; `wc -l AGENT.md` ≤ 250.
- La description cite nommément `/vf-design` **et** `/vf-spike` (démarcation croisée).
- `bash plugin/conductor/scripts/check-agents.sh` vert.

## Risques / points d'attention

- **Frontière `vf-sketch` / `vf-spike`** : les deux sont « jetables ». La démarcation est le
  livrable — visuel non fonctionnel d'un côté, code fonctionnel jeté de l'autre. Elle doit être
  lisible dans les **deux** descriptions : le pendant côté `vf-spike` appartient au plan 12-02.
  Point de couture entre deux plans parallèles, à revérifier en 12-06 (T12).
- Le module `design-orchestrator` n'a pas de suite de tests propre : la vérification passe par
  `check-agents.sh` et par le contrôle T12 côté `dev-orchestrator`, qui doit donc savoir lire les
  descriptions des deux modules.
