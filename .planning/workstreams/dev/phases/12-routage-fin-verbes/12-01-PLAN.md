# Plan 12-01 — Fondations : doctrine de routage, rule de préséance, gabarit de description

## But

Poser les deux briques structurantes dont dépendent toutes les autres (niveau 2 et niveau 3 de la
spec §2), et figer le contrat de rédaction que les 33 descriptions appliqueront. Rend vrais les
critères de succès 4 et 5 du ROADMAP (rule ≤ 40 L globale ; `intent-routing.md` à 100 %).

## Exigences couvertes

VERB-04 (rule de préséance), VERB-05 (couverture 100 %), VERB-03 (le gabarit — son *application*
est portée par 12-02/12-03/12-04). Décisions D-01, D-02, D-05 du CONTEXT.

## Tâches

1. **`plugin/dev-orchestrator/references/intent-routing.md`** (nouveau) — doctrine de routage :
   - En-tête : rôle du fichier, **chargement on-demand** (chemin d'install D7 :
     `.claude/agents/dev-orchestrator-references/intent-routing.md`), et distinction explicite
     d'avec `gsd-skills-index.md` (*auto-généré par `build-gsd-index.sh`, NE PAS ÉDITER* — celui-ci
     est l'inventaire factuel, `intent-routing.md` est la doctrine, écrite à la main et versionnée).
   - Table principale `intention (formulations FR) → verbe /vf-* → cible GSD`, groupée par familles :
     cadrage & amont · construction · qualité & audits · cycle de vie projet · contexte & session ·
     design · méta-outillage.
   - **Couverture intégrale des 65 skills `gsd-*` de l'index**, y compris ceux sans verbe dédié
     (`gsd-ns-*`, `gsd-help`, `gsd-update`, `gsd-settings`, `gsd-config`, `gsd-health`, `gsd-stats`,
     `gsd-thread`, `gsd-manager`, `gsd-workspace`, `gsd-workstreams`, `gsd-review`,
     `gsd-profile-user`, `gsd-pr-branch`, `gsd-ultraplan-phase`, `gsd-plan-review-convergence`,
     `gsd-eval-review`, `gsd-ai-integration-phase`) : ceux-là sont routés **directement par l'agent
     `vibeflow-dev`**, colonne verbe = « — (agent) ».
   - Ligne `/vf-ingest` présente avec `gsd-ingest-docs` + `gsd-import`, **marquée « Phase 13 »** :
     la place est réservée, le verbe n'est pas livré ici.
   - Renvois : `vocabulary-map.md` pour le reframe, `rules/vf-verb-precedence.md` pour la préséance.
   - **Ne pas** dupliquer la table courte de `AGENT.md` (12-05) ni les descriptions (12-02/04).
2. **`plugin/dev-orchestrator/rules/`** (nouveau dossier) + **`vf-verb-precedence.md`** :
   - **Aucun frontmatter `paths:`** — rule globale Tier 1 (Pattern 05) : une intention n'a pas de
     chemin de fichier, elle est inscopable par construction.
   - **≤ 40 lignes** (contrepartie assumée de l'anti-pattern « rule globale qui pollue le
     contexte ») : pas de redite de la table de routage.
   - Contenu minimal : ADR applicables · **Iron Law** · échappatoire cadrée · **exception
     explicite** (un verbe `/vf-*` invoque évidemment sa cible — l'interdit porte sur l'invocation
     *en entrée de chaîne*) · pièges connus · renvoi vers `intent-routing.md`.
3. **Vérifier (sans modifier)** que l'installeur gère déjà `rules/*.md` :
   `plugin/_internal/vibeflow-update.sh` — installation Type 5 (`rules/*.md` → `$TARGET_ROOT/rules/`)
   et désinstallation symétrique. **Aucune modification de l'installeur dans ce plan.**
4. **`.planning/phases/12-routage-fin-verbes/12-DESCRIPTION-TEMPLATE.md`** — gabarit de description :
   - Les 3 blocs de la spec §2.1 : formulations FR réelles (verbes conjugués, tournures réellement
     tapées) · contre-exemples `✘ pas pour <geste voisin> → <verbe voisin>` · portée d'invocation.
   - Squelette YAML copiable (`name` / `description: >`), calqué sur `skills/vf-map/SKILL.md`.
   - **Matrice des 6 paires de collision** à démarquer par contre-exemples croisés :
     `vf-test`↔`vf-testgen` · `vf-review`↔`vf-gaps` · le quatuor
     `vf-brainstorm`/`vf-explore`/`vf-spike`/`vf-spec` · `vf-map`↔`vf-learn` ·
     `vf-progress`↔`vf-resume` · **`vf-gaps`↔`/vf-audit`** (6ᵉ paire, D-01).
   - Interdits de rédaction : aucun « GSD » / « Superpowers » / nom de skill brut dans la
     description ; reframe systématique via `vocabulary-map.md` ; corps du skill = délégation, zéro
     logique d'outil réimplémentée ; ≤ 500 L.
   - Mention en tête : **artefact de planification, non livré dans le module**.

## Risques / points d'attention

- **Dérive de densité** de la rule : la tentation est d'y recopier la doctrine. Parade : la rule
  *renvoie*, elle ne *duplique* pas ; le contrôle `wc -l ≤ 40` est fait avant commit.
- **Faux positifs de couverture** : `gsd-index` (issu de `build-gsd-index.sh`) et `gsd-sdk` ne sont
  pas des skills. La vérification se fait sur les lignes `| gsd-… |` de la table de l'index, pas sur
  une extraction de tokens.
- **`gsd-skills-index.md` régénérable** : ne jamais l'éditer pour faire passer la couverture — c'est
  `intent-routing.md` qui s'aligne sur l'index, jamais l'inverse.
