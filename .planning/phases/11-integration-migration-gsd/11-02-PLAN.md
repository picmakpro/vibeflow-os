# Plan 11-02 — Références SDK : gsd-sdk → gsd-tools

## But

Migrer les 3 sites vivants qui invoquent l'ancien binaire `gsd-sdk` (déprécié — Phase 10 §0)
vers `gsd-tools`, en s'appuyant sur le mapping **prouvé empiriquement** au spike sandbox de la
Phase 10 : `gsd-sdk query roadmap.analyze` → `gsd-tools roadmap analyze`. Renomme la whitelist de
test en conséquence.

Complète une partie du critère de succès 2 du ROADMAP (GSDM-05 — « les références docs pointent
la nouvelle source »). Deuxième plan de la chaîne, dépend de 11-01 (même famille de renommage
paquet, pas de dépendance de fichier réelle mais séquencement imposé par le squelette figé des 6
vagues).

## Exigences couvertes

GSDM-05 (partiel — volet « références docs pointent la nouvelle source » pour le SDK ; le volet
« index régénéré » est en 11-03).

## Risques / points d'attention

- **Ne pas toucher `ensure-deps.sh` dans ce plan** — son propre `command -v gsd-sdk` (piège n°1)
  est déjà traité en 11-01 (suppression pure, pas un renommage vers `gsd-tools`, car ce test
  PATH ne doit tout simplement plus exister).
- **Ne pas inventer de nouvelle commande `gsd-tools`** au-delà de `roadmap analyze` — c'est le
  seul site vivant trouvé après lecture exhaustive du repo (`init.progress` et `state-snapshot`
  du mapping Phase 10 §0 n'ont aucun site d'appel vivant dans ce repo ; le mapping est documenté
  dans `11-CONTEXT.md` D-05 pour référence future, pas à câbler ici).
- **Le fallback `grep -c '^- \[ \]'` doit rester identique au caractère près** — c'est un contrat
  de dernier recours déjà éprouvé (Phase 10 note : « jamais de blocage silencieux sur l'outil
  manquant »), une reformulation involontaire romprait sa portée.
