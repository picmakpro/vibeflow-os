### Finding A — `check-phase-invariants.sh` I2 : faux négatif reproductible sur `plugin/validator/AGENT.md`

`tools/check-phase-invariants.sh --main-ref origin/main` (sous `LC_ALL=C`, voir Finding C) rend :
```
ECART I2 | ac2b38403e295fdb0ff777b377d4bb6782a147c3 | plugin/validator/AGENT.md : LINE_MISMATCH 1
ECART I2 | - | fichiers distincts verifies=2 < min-agents=3
INVARIANTS : M=ok I1=ok I2=ko (fichiers=2) I3=ok I4=ok

```
Seuls trois commits propres à la branche touchent un chemin gardé I2
(`plugin/[module]/AGENT.md` ou `plugin/[module]/agents/*.md`) sur toute la Phase 40.1 :
`f2c60d6` (conductor, plan 04), `b67172c` (kpi-analyst, plan 12), `ac2b384` (validator, plan 11).
Les deux premiers passent proprement (paire de valeurs 250→300 pures). Le troisième
(`ac2b384`, message : « remplacement de valeur seul (250→300L, deux occurrences), aucune ligne ni
instruction ajoutée ou retirée ») est rejeté par erreur.

**Diagnostic tracé manuellement** — le diff réel de `ac2b384` :
```diff
-- **Densité ADR-029** : tous les `.claude/agents/*.md` ≤ 250 lignes, tous les
++ **Densité ADR-029** : tous les `.claude/agents/*.md` ≤ 300 lignes, tous les
-- ❌ Corriger automatiquement un agent > 250L (auto-refactor = perte de nuance)
++ ❌ Corriger automatiquement un agent > 300L (auto-refactor = perte de nuance)
```
La fonction `swap()` de `pair.awk` (dans `check-phase-invariants.sh`) remplace **tous** les
nombres d'une ligne retirée par `300`, sans distinguer le nombre qui a réellement changé. Sur la
ligne 69, elle transforme aussi `ADR-029` (une référence textuelle inchangée) en `ADR-300` :
```
REMOVED_SWAPPED: - **Densité ADR-300** : ... ≤ 300 lignes ...
ADDED          : - **Densité ADR-029** : ... ≤ 300 lignes ...
```
Les deux chaînes ne concordent plus → `LINE_MISMATCH 1` rapporté à tort. Le contenu réel du commit
est un remplacement de valeur pur et légitime ; c'est l'heuristique de l'outil qui est en défaut
sur toute ligne portant un second nombre non lié au plafond (ici « ADR-029 »). La suite
`test-check-phase-invariants.sh` (13/13 ok, rejouée) ne couvre pas ce cas — aucun de ses fixtures
ne place un nombre non-plafond adjacent au nombre swappé dans le texte d'une ligne modifiée.

**Conséquence :** `fichiers distincts verifies=2 < min-agents=3` → I2 rouge → `check-phase-invariants.sh`
rc 1. Aucun quatrième candidat n'existe dans l'historique de la Phase 40.1 (vérifié : aucun autre
commit ne touche `plugin/*/AGENT.md` ou `plugin/*/agents/*.md` dans `61d80bf..HEAD`) — ce plancher
de 3 fichiers n'est donc pas atteignable sans corriger l'outil, ce qui est hors du périmètre déclaré
de ce plan (`files_modified` ne liste que `.planning/REQUIREMENTS.md`, `.planning/BACKLOG.md`,
`40.1-VALIDATION.md`).

**Non contourné** : aucune modification de `tools/check-phase-invariants.sh`, aucune exclusion,
aucun changement de `--min-agents`. Remonté tel quel.

### Finding B — ref locale `main` déplacée vers HEAD pendant l'exécution (environnement, pas cette branche)

En cours de Task 2, `bash tools/phase-base.sh` (sans argument, forme littérale du plan) résolvait
`base=HEAD` au lieu de `61d80bf` (`origin/main`), rendant `NONMERGES` vide et I1/I2 faussement à 0.
Diagnostic :
```
git reflog show --date=iso main | head -2
713c621 main@{2026-09-16 23:13:23 +0200}: branch: Reset to 713c621
61d80bf main@{2026-09-16 21:48:20 +0200}: branch: Reset to origin/main
```
La ref locale `main` a été repointée sur `713c621` (= HEAD de cette branche) à 23:13:23, pendant
que ce mandat était en cours d'exécution (Task 0 avait vérifié `main=origin/main=61d80bf` juste
avant). `driver-lock.sh status` confirme un seul détenteur (`vf-dev-manager-40.1-exec`,
`session_ids: ["f71fce44-..."]`, celui de ce mandat) — pas de tiers hostile visible dans le lock,
donc vraisemblablement un effet de bord d'une opération du manager lui-même (ex. préparation du
worktree propre au sha `713c621` cité dans le mandat, si elle a créé/déplacé une branche locale
`main` au lieu d'un checkout détaché). Cette ref est **partagée entre tous les worktrees** de ce
dépôt (`.claude/worktrees/*`) — un `git branch -f main <sha>` ou `git checkout -B main <sha>` dans
n'importe lequel d'entre eux l'affecte partout, y compris ici.

**Action prise** : aucune écriture sur `main` (hors périmètre, refs partagées). Contournement en
lecture seule via `--main-ref origin/main`, mécanisme documenté par `phase-base.sh` lui-même pour
exactement ce cas (« main locale non fiable/divergée »), et dont la légitimité du choix
(`origin/main`) est déjà prouvée par Task 0 (contenu du hotfix + pointe de main confirmés dessus).
**Remonté au manager** : la ref locale `main` de ce dépôt partagé doit être vérifiée/restaurée avant
toute autre opération qui s'y fierait implicitement.
