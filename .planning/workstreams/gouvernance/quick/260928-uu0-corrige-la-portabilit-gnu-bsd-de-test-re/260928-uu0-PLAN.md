# Correction de portabilité GNU/BSD — test-recalc-planning.sh (R14/MUT-CHMOD/MUT-CHMOD-JOURNAL)

## Contexte

CI GitHub (runner Linux ubuntu-latest, run 36430707398, commit ca185e4) : `test-recalc-planning.sh`
rend `179 OK · 1 KO`, `✗ R14 permissions`. Cause : `MODE=$(stat -f "%Lp" f 2>/dev/null || stat -c
"%a" f 2>/dev/null)`. Sous GNU coreutils, `stat -f` désigne le système de fichiers, pas le format
de sortie — `"%Lp"` est pris pour un nom de fichier, la commande échoue (code non nul) mais imprime
déjà un bloc `File: ... ID: ... Type: ...` sur stdout avant d'échouer ; le repli `stat -c "%a"`
s'exécute ensuite et imprime `644` à la suite, dans la MÊME substitution de commande. `MODE` devient
une chaîne multi-ligne concaténée, jamais égale à `"644"`. Même motif, copié-collé, en deux autres
endroits (MUT-CHMOD, MUT-CHMOD-JOURNAL). Sur macOS (poste de dev), `stat -f "%Lp"` réussit
directement (sémantique BSD) : le défaut n'apparaît jamais localement.

## Tâche 1 — mode_octal() portable, remplace les 3 sites `stat -f`/`stat -c`

**Fichier** : `plugin/planning-core/scripts/tests/test-recalc-planning.sh`
**Action** :
- Ajoute une fonction `mode_octal()` juste après la détection de `$PYBIN` (déjà une dépendance
  de la suite — 90 appels existants) : `mode_octal() { "$PYBIN" -c 'import os,sys; print(format(os.stat(sys.argv[1]).st_mode & 0o777, "o"))' "$1"; }`.
  Une seule sémantique côté appel système (`os.stat().st_mode`), identique GNU/Linux et BSD/macOS —
  élimine toute dépendance au binaire `stat` du PATH.
- Remplace les 3 sites :
  - R14 (permissions umask 0077) : `MODE=$(stat -f "%Lp" ... || stat -c "%a" ...)` → `MODE=$(mode_octal "$R14_DIR/.planning/$f")`
  - MUT-CHMOD : `MODE_INDEX=$(stat -f ... || stat -c ...)` → `MODE_INDEX=$(mode_octal "$DIR_CAS/.planning/INDEX.md")`
  - MUT-CHMOD-JOURNAL : `MODE_CLOTURE=$(stat -f ... || stat -c ...)` → `MODE_CLOTURE=$(mode_octal "$DIR_CAS/.planning/cloture.log")`
**Verify** :
- `bash -n plugin/planning-core/scripts/tests/test-recalc-planning.sh` → 0
- `bash plugin/planning-core/scripts/tests/test-recalc-planning.sh` sous macOS → `313 OK · 0 KO`
  (compte exact attendu, inchangé — aucun test ajouté/retiré)
- Simulation locale (faux `stat` GNU-like placé en tête de PATH, imprime un bloc `File:` sur `-f`
  puis échoue, imprime le mode réel sur `-c "%a"`) : l'ancienne ligne produit une chaîne
  multi-ligne `[  File: "..." ... 644]` et échoue la comparaison `"644"` ; `mode_octal()` rend
  `[644]` propre, sans jamais consulter le binaire `stat` du PATH.
**Done** : les 3 sites ne référencent plus `stat -f`/`stat -c` ; `mode_octal` est la seule voie de
lecture de mode dans le fichier.
