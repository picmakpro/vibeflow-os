## Corrections de prémisses du mandat — vérifiées sur disque avant d'écrire ce plan

**`VF_NOTIFY_BIN_DIR` n'est pas lue par `notify.sh` — code MORT, pas une absence.** Le mandat de
planification cite cette variable comme déjà présente dans `notify.sh`, « même rôle que
`VF_NOTIFY_FORCE_CHANNEL`/`VF_NOTIFY_BIN_DIR` déjà dans `notify.sh` ». Fait vérifié (`grep -c
VF_NOTIFY_BIN_DIR plugin/conductor/scripts/notify.sh plugin/conductor/scripts/tests/test-notify.sh`
rend `0` pour les deux) : `notify.sh` ne la lit nulle part, et `test-notify.sh` ne l'exporte pas
non plus. Mais l'affirmation « n'apparaît nulle part dans le code livré » était FAUSSE : elle est
bien exportée, trois fois, dans `plugin/conductor/scripts/tests/test-dag.sh:741,769,849` (`export
VF_NOTIFY_BIN_DIR="$UTIL_DIR_NOTIFY"`, sans effet — `notify.sh` ne la consulte jamais, cf. le
commentaire de `test-dag.sh:845` lui-même : « sans effet »). C'était un nom de variable mentionné
dans le texte d'action de `33-04-PLAN.md` (jamais consommé côté production : `test-notify.sh`
isole ses shims par des répertoires `N1_DIR`/`N2_DIR`/… préfixés directement au `PATH`, sans
variable nommée dédiée ; `test-dag.sh` l'exporte par cohérence avec ces autres tests mais elle
reste inerte). Ce plan n'introduit donc pas de second override « bin dir » et ne
réutilise QUE `VF_NOTIFY_FORCE_CHANNEL` comme précédent réel pour nommer `VF_NOTIFY_OPTIN_FILE`.

**La branche résiduelle `*) : ;;` n'est PAS rendue unilatéralement inerte par le nouveau gate.**
Le mandat suggère que « le nouveau gate intercepte AVANT elle » comme motif suffisant pour la
laisser telle quelle — vrai uniquement pour le chemin PAR DÉFAUT (sentinel absent). Si l'opt-in
est ARMÉ et que `VF_NOTIFY_FORCE_CHANNEL` porte une valeur hors `windows`/`darwin`/`linux`
(`none`, `off`, une faute de frappe), la cascade assigne quand même `channel="<valeur>"` et le
dispatch tombe dans `*) : ;;` — EXACTEMENT comme avant ce plan. La décision de la laisser ainsi
(voir truths) repose sur la portée littérale de D-33-H (le défaut d'émission, pas la validation
d'un override de test), pas sur une inertie totale qui n'existe pas.
</deviation>
