<interfaces>
Extension du format du banc :
- `@@ fichier-dehors <chemin>` : fichier créé HORS de la racine du lab, dans un bac à sable
  frère propre au lab (contenu = lignes suivantes).
- `@@ lien <chemin> -> <cible>` : lien symbolique ; `<cible>` = chemin relatif, ou `DEHORS/<x>`
  que le matérialiseur résout vers le fichier ou dossier `<x>` du bac à sable frère.
- `@@ attendu-hors-modele <chemin> :: <type>` (type `fichier` | `dossier` | `lien` | `autre`,
  chemin relatif à `.planning/`) : quand un lab en porte au moins une, le coureur exige que
  `hors_modele` du JSON soit EXACTEMENT cet ensemble ; `@@ attendu-hors-modele-aucun` exige une
  liste vide.

Classement (`classer_entrees`) : racine de `.planning/` — `cycles`, `baux`, `missions` doivent être
des dossiers, `PROJECT.md`, `REQUIREMENTS.md`, `config.json`, `INDEX.md`, `STATE.md`,
`cloture.log`, `.recalc-cache.json` des fichiers réguliers ; `ANNEXES = ("_archive", "_bancs",
"intel", "recherches", "registres", "sketches")` doivent être des dossiers (jamais lus) ; tout le
reste, un emplacement du mauvais type et tout lien symbolique → hors modèle. Arbre du modèle — dans
`cycles/` : dossiers d'unité au nom valide ; dans un cycle : `CYCLE.md`, `phases` ; dans `phases/` :
dossiers d'unité ; dans une phase : `CADRAGE.md`, `PLAN.md`, `CLOTURE.md`, `VERDICT.md`,
`SUMMARY.md`, `DEROGATION.md`, `plans` ; dans `plans/` : dossiers d'unité ; dans un plan : `PLAN.md`,
`CLOTURE.md`, `VERDICT.md`, `SUMMARY.md`, `DEROGATION.md`. Tout autre nom, un nom d'unité invalide,
un dossier d'unité en lien → hors modèle (chemin relatif à `.planning/`), jamais parcouru. Un
fichier du modèle au bon nom mais non régulier reste traité par Φ1 (`fichier-non-regulier:<nom>`).
INDEX.md : `## Hors modèle` puis une ligne `` - `<chemin échappé>` (<type>) `` par entrée, triée.
`echapper_nom` : tout caractère de catégorie Unicode C* devient `\uXXXX`, l'accent grave devient
`` \` ``.

Cache (`.planning/.recalc-cache.json`, mode écriture seulement) : objet JSON
{`cache_schema_version`: 1, `moteur`: "recalc-planning", `unites`: {chemin: {`signature`, `ecrit`,
`livrables`, `etat`, `raison`, `meta`}}}, écrit par `ecrire_si_different` (listé dans `ecrits`
quand réécrit). `signature_unite` = sha256 du texte canonique : liste triée des entrées du dossier
de l'unité (nom + type) + (nom, sha256 du contenu) de chaque fichier du modèle lu + pour un plan le
sha256 du CADRAGE.md de sa phase. Reprise d'une unité ⇔ signature identique ET booléens
d'existence des livrables recalculés identiques. `charger_cache` → statut `absent` | `illisible`
(JSON invalide, lien symbolique, non régulier, non UTF-8) | `autre-format` (racine non objet,
`cache_schema_version` absent ou différent, `moteur` différent, `unites` non objet, entrée mal
formée) | `valide` ; tout statut autre que `valide` → recalcul complet. Rapport d'écriture : ajoute
`cache`, `unites_recalculees`, `unites_reprises`. Les agrégations (phase à plans, cycle) sont
recalculées à chaque passage à partir des feuilles.
