## Interface de l'avancement (contrat figé, lu par la Phase 68)

- Objet : `{ version: 1, etat, plans: { faits, total }, correctifs, mission, reste }` ; `etat` ∈ `ETATS` =
  `['a-faire', 'en-cours', 'a-recetter', 'fait']` ; `mission` = `{ nom, etat }` ou `null`, `nom` = nom du fichier DAG sans
  `.dag.json`, `etat` ∈ `running`, `failed`, `done`, `ready` (vocabulaire de `dag.sh`) ; `reste` ⊆ `RESTE` =
  `['recette', 'verification', 'cloture']`, dans cet ordre. Ajouts de champs seulement en version 1 ; tout retrait ou
  renommage = version 2.
- Évaluation de `etat` : `fait` si la case de ROADMAP est cochée ; sinon `a-recetter` si `plans.total > 0` et
  `plans.faits === plans.total` ; sinon `en-cours` si `plans.faits > 0` ou si une mission rattachée a un nœud `running` ;
  sinon `a-faire`. Ni `current_phase` ni le compartiment actif n'entrent dans le calcul.
- `etatMission(nodes)` : `running` si un nœud l'est, sinon `failed` si un nœud l'est, sinon `done` si tous le sont (et au
  moins un nœud), sinon `ready`. Plusieurs missions rattachées : `mission` désigne d'abord celle qui a un nœud `running`,
  puis la plus petite règle de rattachement, puis le nom le plus petit.
