## Interfaces fournies (signatures figées ici, lues par 79-06, 79-09, 79-12, 79-13, 79-15 et les Phases 75, 76, 77)

Module `vf-cockpit-routes.mjs` (aucune dépendance, aucun fichier lu, aucun processus) :
- `HISTORIQUE`, `FLUX` : marqueurs de régime (chaînes figées). Un lecteur sans marqueur est « gardé ».
- `reponse(code, corps, entetes)` : réponse personnalisée (objet gelé reconnu par `estReponse`) pour un code autre que 200, des en-têtes ajoutés (`ETag`, `Vary`) ou une réponse sans corps (304).
- `controlerAcces(req, { entete, jetonValide, port })` -> `{ ok: true }` ou `{ ok: false, code }` : C0 « Accès ». Ordre : hôte (en minuscules, `127.0.0.1:<port>` ou `localhost:<port>`, le port étant `port` ou, à défaut, le port local de la socket), origine (absente ou égale à `http://` suivi de l'hôte tel que reçu), jeton (`jetonValide(req.headers[entete])`, la comparaison en temps constant est celle de l'appelant), méthode (GET). Les trois premiers refusent en 403, le dernier en 405. Paramètre manquant ou invalide : refus 403 (fermé par défaut).
- `creerRepartiteur({ table, contexte, repondre, json, acces, log })` -> `{ servir(req, res, url) }`. La table est validée à la création (tableau de `[chemin, lecteur, régime]`, chemin commençant par `/api/vf/`, chemins uniques, lecteur fonction, régime absent ou `HISTORIQUE` ou `FLUX`) : une table invalide fait échouer le démarrage, jamais une requête. `servir` rend vrai quand le chemin est dans la table, faux sinon.

Module `vf-cockpit-server.mjs` :
- `ROUTES` : la table. Une ligne par route, `[chemin, lecteur, régime?]`, ordre alphabétique par chemin (A10, contrôlé par RK.2 : aucun repère de phase dans cette table). La table vit dans `vf-cockpit-server.mjs` (A10), pas dans `vf-cockpit-routes.mjs`. Ajouter une route = importer le lecteur de la phase et ajouter UNE ligne à sa place alphabétique ; rien d'autre (ni contrôle, ni en-tête, ni garde, ni gestion d'erreur).
- Lecteur : `lecteur(ctx, req, url)` rend un corps JSON sérialisable (200), ou `reponse(...)`, ou une promesse de l'un ou de l'autre ; `ctx` est gelé et porte `root`, `here`, `log(cat, msg)`, `dep`, `clients`, `journal`, `live` (accesseur : poignée du direct ou null) et `fluxFerme()`. Un lecteur `FLUX` reçoit en plus `res` en quatrième argument et écrit lui-même (seul `events`).
- `repondreGardee(req, res, corps, { code, entetes, acces, log })` : contrôle d'accès (`acces(req)` obligatoire : absent, elle lève une erreur plutôt que de répondre sans contrôle), puis garde, puis en-têtes, puis écriture. Un 503 `emission-refusee` ne cite jamais le corps. Les en-têtes `access-control-*`, `content-type` et `cache-control` fournis par l'appelant sont ignorés ; `no-store` est toujours posé.
- `attach({ here, root, token, inject, log, routes = ROUTES })` : `routes` est le point d'extension d'essai. Les trois derniers crochets (`avantQuestion`, `modes`, `argsAgent`) et les valeurs rendues ne changent pas.
