# External Integrations

**Analysis Date:** 2026-06-04

## APIs & External Services

**Claude Code (Anthropic):**
- Service: Claude Code runtime and AI models
- What it's used for: Skill/agent execution, evaluation of skill descriptions, LLM-based improvement loops
- SDK/Client: Claude Code CLI (`claude` command)
- Auth: Session-based via Claude Code authentication (inherited by subprocess calls)
- Location: `skill-creator/skills/skill-creator/scripts/run_eval.py` (subprocess invocation), `improve_description.py`

**GitHub:**
- Service: Source repository and release management
- What it's used for: Module distribution via git clone, version control
- SDK/Client: `git` CLI + `gh` CLI (optional)
- Auth: SSH key or `gh` CLI session authentication
- Location: `_internal/vibeflow-update.sh`, INSTALL.md
- Repository URL: `https://github.com/picmakpro/vibeflow-os.git` (private repo)

## Data Storage

**Databases:**
- None - This is a module distribution repository, not a stateful application

**File Storage:**
- Local filesystem only
  - Cache: `.vibeflow-cache/` (git clone of vibeflow-os repo)
  - Installation targets: `.claude/skills/`, `.claude/scripts/`, `.claude/agents/`, `.claude/rules/`
  - Backups: `.claude/.backups/` (automatic backup before updates)
  - Logs: `.claude/logs/` (audit and archive logs)
  - Memory registry: `.vibeflow-installed` (module installation manifest)

**Caching:**
- `.vibeflow-cache/` - Shallow git clone (depth 1) used to cache module updates locally
- Synced via `vibeflow-update.sh sync` command

## Authentication & Identity

**Auth Provider:**
- None required for module operation
- GitHub authentication optional (required only for private repo access when installing)
  - Mechanism: SSH key or `gh CLI` session
  - See INSTALL.md for setup

**Authorization:**
- No API keys or credentials stored
- Lab inherits authentication context from Claude Code session

## Monitoring & Observability

**Error Tracking:**
- None external
- Local logging to `.claude/logs/`

**Logs:**
- Shell scripts: stderr output with `[vibeflow-update]`, `[audit-infra]`, `[archive.sh]` prefixes
- Python scripts: stdout/stderr with structured JSON output (where applicable)
- Audit logs: `INFRASTRUCTURE_SNAPSHOT.md` generated by `audit-infra.sh`
- Archive logs: `.claude/logs/archive.log` (timestamped entries)

## CI/CD & Deployment

**Hosting:**
- GitHub (private repository)

**CI Pipeline:**
- None detected in main repo
- Individual module tests via `scripts/tests/test-*.sh` files
- Example: `consolidator/scripts/tests/test-consolidator.sh`

**Module Distribution:**
- Manual installation via `vibeflow-update.sh install <module>`
- Automatic update via `vibeflow-update.sh update <module>`
- Rollback via `vibeflow-update.sh rollback <module>`

## Environment Configuration

**Required env vars:**
- None mandatory
- Optional configuration:
  - `VIBEFLOW_CACHE`: Cache directory (default `.vibeflow-cache`)
  - `MEMORY_DIR`: Memory directory (default `.claude/memory`)
  - `ARCHIVE_DIR`: Archive directory (default `$MEMORY_DIR/archive`)
  - `ALLOWLIST`: Archive allowlist file (default `.claude/scripts/archive.allowlist`)
  - `LOG_FILE`: Log file path (default `.claude/logs/archive.log`)
  - `VF_ARCH_WARN`: File size warning threshold (default 250 lines)
  - `VF_ARCH_BLOCK`: File size blocking threshold (default 300 lines)

**Secrets location:**
- Not applicable - no credentials stored
- GitHub authentication: Use SSH key or `gh CLI` session (system-wide)

## Webhooks & Callbacks

**Incoming:**
- None

**Outgoing:**
- Optional hooks defined in lab's `.claude/settings.json`:
  - `SessionEnd` hook: async call to `archive.sh` for memory consolidation (INSTALL.md example)
  - Infrastructure audit hook: `audit-infra.sh` for drift detection post-update

## Subprocess Calls to Claude Code

**Pattern:**
- Python scripts invoke `claude -p` via subprocess to trigger evaluations
- Location: `skill-creator/skills/skill-creator/scripts/run_eval.py`, `improve_description.py`
- Input: Skill description or prompt via stdin
- Output: Text response captured from stdout
- Environment: `CLAUDECODE` env var removed to prevent nesting conflicts
- Model selection: Optional `--model` flag supported

## Internal Communication

**Module-to-Module:**
- No direct communication
- Coordination via lab's memory system (ADRs, ITERATION_LOG, etc.)
- Validator (`validator/AGENT.md`) delegates to individual skills via invocation:
  - `consolidator` - Memory consolidation
  - `infrastructure-audit` - Technical audit
  - `agent-density-auditor` - Agent conformance
  - `audit-architecture` - Architecture structure validation
