<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| arbre source → lab installé en CI | La CI est le seul endroit où l'on observe ce que l'install POSE, sur une machine neuve. |
| journal de CI → confiance dans la preuve | Un job vert qui n'a rien exercé produit une confiance fausse, plus dangereuse qu'un rouge. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-30-08-01 | Spoofing | job de CI vert sans rien exercer | high | mitigate | Garde anti-vert-à-vide sur le nombre d'entrées VF posées, prouvée à la main sur un settings.json vide ; garde anti-découverte-vide du job de tests conservée ; le journal affiche le compte exercé et le checkpoint humain le vérifie. |
| T-30-08-02 | Tampering | preuve portant sur l'arbre source au lieu du lab | high | mitigate | Les assertions s'exécutent sur le settings.json POSÉ par l'install dans le lab de CI — c'est le patron `as-installed` de la Phase 28, né précisément de la régression #38. |
| T-30-08-03 | Repudiation | portabilité Windows revendiquée sans poste Windows | medium | accept | Aucun runner Windows n'existe dans ce dépôt. La simulation (retours chariot, antislashs, stub du magasin d'applications) est le repli explicite d'ADR-054 ; l'acceptation est BORNÉE à ce vecteur et NOMMÉE dans le commentaire de l'étape, jamais implicite (ADR-070 : une acceptation borne son vecteur, pas le risque en bloc). |
| T-30-08-04 | Elevation of Privilege | exécution de code du dépôt sur le runner | low | accept | Le workflow n'ajoute aucune source externe ni aucun secret ; il installe des modules du dépôt lui-même dans un répertoire temporaire, comme les jobs existants. |
| T-30-08-SC | Tampering | installs npm/pip/cargo | low | accept | Aucun paquet installé par ce plan (le job utilise les outils déjà déclarés par le runner). |
</threat_model>
